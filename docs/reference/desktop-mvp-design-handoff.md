# Desktop MVP 디자인 이관

현재 Penpot 확정 화면을 기존 Electron 앱으로 옮기기 위한 안내다. 디자인 상태와 저장소 구현의 차이를 기록하며, 기존 검색·상세 API·인증·캡처 Rule을 대체하지 않는다. 이 문서의 작성은 프론트엔드 구현이나 Windows 검증의 완료를 뜻하지 않는다.

## 디자인 원본

| 용도 | Penpot 원본 | 읽는 방법 |
| --- | --- | --- |
| 메인 화면 | [01 · 다크 · 대기][main] | 같은 페이지의 02~06에서 캡처 중·창 감지 실패와 라이트 테마를 확인한다. |
| 반응형 배치 | [확정 A · 900px][responsive] | 같은 이름의 700px·500px·300px 보드까지 비교한다. |
| 메인 슬롯의 면 전환 | [08 · 카드 순환 · 상태 비교][faces] | 캐릭터 → 장비 → 서약 → 투자 현황 → 캐릭터. 슬롯마다 독립적이다. |
| 별도 상세창 | [07 · 캐릭터 상세 · 확정 A][detail] | 장비·서약·강화·마법부여·스킬트리를 각각 한 장으로 둔, 반듯하게 겹친 카드 A안이다. |

`보관`으로 시작하는 보드와 09B·09C는 구현 기준에서 제외한다. Penpot의 메인 카드 일부는 시연용 상세창 링크를 가지고 있으므로, 클릭 링크를 그대로 복제하기보다 08의 면 전환과 상세 열기 액션을 구분한다. 프로토타입의 화면 이동은 실제 입력·API 호출·Electron 창 수명 구현을 대신하지 않는다.

## 메인 화면과 슬롯

디자인 기준은 바깥 좌우 24px, 위 16px, 헤더 아래 16px, 본문 안쪽 16px, 카드 간격 12px다. 카드 높이는 280px이며 폭은 반응형으로 변한다.

| 화면 폭 | 한 줄 카드 수 | 카드 폭 |
| --- | --- | --- |
| 900px | 4 | 196px |
| 700px | 3 | 약 199px |
| 500px | 2 | 204px |
| 300px | 1 | 220px |

위 값은 확인할 디자인 표본이며 각 숫자를 breakpoint로 그대로 사용한다는 뜻은 아니다. 중간 폭에서도 줄바꿈·간격·가독성이 이어지도록 구현한다. 새로고침이나 다른 슬롯의 조작 때문에 한 슬롯의 카드 면이 바뀌지 않도록 상태를 분리한다.

기본 면에는 중앙 캐릭터 이미지 아래 모험단명·이름 입력·직업·명성을 배치한다. 장비·서약 면에는 이름·서버를 반복하지 않는다. 장비 아이콘 위 강화·증폭 숫자, 마법부여 마름모, 크리티컬·스위칭 표시는 최종안에서 제거됐다. 강화 수치와 마법부여 등급은 투자 현황 면의 12부위 목록에서 확인한다.

| 상태 | 카드 본문 | 이름 입력 | 상세 열기 |
| --- | --- | --- | --- |
| 조회 완료·캐릭터 선택됨 | 한 번 누를 때마다 다음 면, 네 번째에 기본 면 | 수정 가능 | 우측 상단 아이콘으로 별도 실행 |
| 이름 수정 중 | 입력과 면 전환을 분리 | 수정·검색 확정 가능 | 다른 캐릭터의 이전 상세를 열지 않도록 처리 |
| 검색 실패 | 빨간 테두리와 실패 안내, 면 전환 없음 | 수정 가능 | 아이콘을 비활성 상태로 표시 |
| 인식 대기·빈 카드 | 호버 반응과 면 전환 없음 | 직접 입력 가능 | 아이콘 없음 |

입력·서버 선택·상세 버튼 조작은 카드 면을 넘기지 않는다. 카드 전체를 하나의 `button`으로 만들고 내부에 input/button을 중첩하지 않는다. 컨테이너 안에 면 전환 버튼과 입력·상세 버튼을 형제 요소로 배치하고, 키보드로도 각각 접근할 수 있게 한다. 상세 아이콘은 호버뿐 아니라 키보드 포커스로도 드러나며, 호버가 없는 환경에서도 사용할 수 있어야 한다.

디자인의 빈 카드는 API의 검색 결과 0건과 같은 뜻이 아니다. 기존 `SearchSlot.state`의 `idle`·`pending`·`success`·`empty`·`failure`를 유지하고, 0건·통신 오류·호출 제한을 동일한 데이터 상태로 합치지 않는다. 검색 중 안내·재시도·429 대기와 OCR 복귀는 기존 기능을 이어받는다. 서버 선택 후보는 실제 검색 결과에 포함된 서버만 사용한다.

## 상세창 A안

1120×680 기준으로 상단 캐릭터 정보·장비 점수·명성을 유지하고, 그 아래 선택된 736×480 카드를 전면에 둔다. 뒤의 카드들은 회전 없이 오른쪽으로 84px, 아래로 8px씩 겹쳐 다른 정보의 존재와 이름이 보인다. 보이는 카드를 누르면 해당 카드가 앞으로 나온다. 현재 프로토타입은 180ms dissolve이며 실제 이동의 느낌은 renderer에서 확인한다. 모션 감소 설정에서는 불필요한 이동을 줄인다.

| 카드 | 내용 |
| --- | --- |
| 장비 | 중앙 캐릭터와 양쪽 장비 슬롯 |
| 서약 | 같은 구도의 서약 슬롯. 상세창의 칭호·오라·크리쳐는 장비 카드와 동일하게 유지 |
| 강화 | 12부위의 강화·증폭 수치. 아이콘 위에 숫자를 겹치지 않음 |
| 마법부여 | 12부위의 종결·준종결·기타 텍스트. 현재 등급은 디자인 예시 |
| 스킬트리 | 구성 예정 상태만 존재. 실제 스킬트리 UI는 후속 범위 |

기존의 “서약으로 전환” 버튼은 없다. 강화와 마법부여는 상세창에서는 별도 카드이며, 메인 08의 작은 투자 현황 면과 구분한다. 12부위 목록에는 칭호·오라·크리쳐를 넣지 않는다. 08의 작은 서약 면과 07 상세창의 슬롯 구성을 무조건 동일하게 만들지 않는다.

## 표현과 이미지

- 글꼴은 나눔스퀘어 네오다. 작은 투자 현황 목록은 10px 일반 두께, 상세 목록은 14px 일반 두께가 기준이다. 테이블의 교차 행 배경은 `#22262C` / `#2B3037`이다.
- 무료 아이콘의 디자인 원본은 [Lucide 아이콘 목록](https://lucide.dev/icons)이다. 현재 사용 중인 sun·moon·camera·x·chevron-down·user·external-link를 기준으로 구현 자산과 출처를 맞춘다.
- 캐릭터 이미지: `https://img-api.neople.co.kr/df/servers/<serverId>/characters/<characterId>?zoom=<zoom>`.
- 아이템 이미지: `https://img-api.neople.co.kr/df/items/<itemId>`.
- 서약 대표 이미지는 임시 [발키리 이미지](https://bbscdn.df.nexon.com/data7/showroom/static/icon/oath_09_valkyrie/00001.png)를 사용한 상태다. 이 그림으로 실제 서약 종류를 판정하지 않는다. 종류별 자산 매핑은 후속이다.

| 장비 희귀도 | 테두리 색상 | 장비 희귀도 | 테두리 색상 |
| --- | --- | --- | --- |
| 커먼 | `#FFFFFF` | 언커먼 | `#68D5ED` |
| 레어 | `#B36BFF` | 유니크 | `#FF00FF` |
| 에픽 | `#FFB400` | 레전더리 | `#FF7800` |
| 크로니클 | `#FF6666` | 태초 | `#50E3C2` |

마법부여 표시색은 종결 `#50E3C2`, 준종결 `#FFB400`, 기타 `#FFFFFF`다. 등급 텍스트를 함께 표시하며 색만으로 판정 결과를 전달하지 않는다. **판정 기준이 없는 실제 데이터를 `기타`로 간주하거나 디자인의 예시 등급을 실사용 캐릭터에 복사하지 않는다.**

## 데이터와 기존 구현 연결

검색은 [캐릭터 검색 계약](../rules/character-search.md), 상세는 [캐릭터 상세 계약](../rules/character-details.md)을 따른다. 공개 검색·상세 조회를 로그인으로 막지 않는다. 상세 API의 캐시·갱신·오류 정책은 원본 계약을 참조하며 UI 문서에서 별도 정책을 만들지 않는다.

| 화면 데이터 | 연결 지점 | 주의점 |
| --- | --- | --- |
| 검색 후보·서버·명성 | `GET /characters`의 `rows` | 응답은 식별자·이름·서버·명성의 다섯 필드뿐이다. 모험단·직업·장비 정보가 있다고 가정하지 않는다. |
| 기본 정보·장착 정보 | `GET /characters/:serverId/:characterId` | 선택한 캐릭터의 상세를 연결한다. `character`, `equipment`, `avatar`, `creature`, `oath` 등을 소비한다. |
| 강화·증폭 | 캐릭터에 실제 장착된 장비 값 | 공용 `itemDetail`의 값으로 덮어쓰지 않는다. |
| 서약 슬롯 | `oath.info`, `oath.crystal`의 `slotNo` | 장비의 부위 ID와 별도로 명시적 대응을 둔다. 아래 표는 현재 디자인의 대응이다. |
| 마법부여 | 장착 데이터와 별도의 평가 기준 필요 | 상세 API는 종결·준종결·기타 판정 결과를 제공하는 계약이 아니다. |
| 스킬 | `skillStyle` 및 `skillDetails` | 데이터가 있다는 이유로 미설계 스킬트리 UI를 MVP에 추가하지 않는다. |

| 서약 원본 | 대응 장비 부위 | 서약 원본 | 대응 장비 부위 |
| --- | --- | --- | --- |
| `info` | 무기 | 결정 `slotNo: 0` | 머리어깨 |
| 결정 `1` | 상의 | 결정 `2` | 하의 |
| 결정 `3` | 벨트 | 결정 `4` | 신발 |
| 결정 `5` | 보조장비 | 결정 `6` | 귀걸이 |
| 결정 `7` | 마법석 | 결정 `8` | 팔찌 |
| 결정 `9` | 목걸이 | 결정 `10` | 반지 |

장비 배열 순서만으로 부위를 결정하지 않는다. 12부위 식별자는 `WEAPON`, `JACKET`, `SHOULDER`, `PANTS`, `WAIST`, `SHOES`, `AMULET`, `WRIST`, `RING`, `SUPPORT`, `MAGIC_STON`, `EARRING`이다. `MAGIC_STON`은 원본 식별자를 유지한다. 누락 슬롯·누락 값·이미지 실패는 실제 0이나 다른 아이템으로 채우지 않는다.

| 저장소 위치 | 이어받을 책임 |
| --- | --- |
| `apps/desktop/src/frontend/src/search/SearchResults.tsx`, `CharacterCandidates.tsx` | 기존 슬롯·후보 표시를 카드 화면으로 연결할 출발점 |
| `apps/desktop/src/frontend/src/search/useCharacterSearch.ts` | 이름 수정·제출·OCR 복귀·슬롯별 검색 상태 |
| `apps/desktop/src/frontend/src/search/capture-search.ts`, `connection.ts` | capture와 요청 수명, 순서·취소·늦은 응답 처리 |
| `apps/desktop/src/backend/search/`, `src/preload/common/types/search.ts` | main 검색 처리와 공유 IPC 계약 |
| `apps/desktop/src/backend/main.ts`, `src/preload/index.ts` | 새 상세 기능의 등록 지점. 기능 본문은 별도 모듈로 구성 |

상세 조회용 Desktop 연결과 별도 상세 BrowserWindow는 새 구현 범위다. 현재 검색 IPC가 이미 상세 조회까지 제공한다고 가정하지 않는다. Renderer에 Neople API key나 임의 URL 호출을 추가하지 않고, 기존 main/preload 경계와 runtime 검증을 따른다. 같은 캐릭터의 카드 면을 바꿀 때마다 새 HTTP 요청을 만들지 않도록 조회 데이터와 표시 상태를 분리한다.

레이아웃은 기존 React·TypeScript·StyleX와 `@ldb/ui`·SEED를 사용한다. [Desktop 스타일 작성](desktop-styling.md), [Design System](../rules/design-system.md), [검색 구현 안내](desktop-character-search.md)의 공용 자산·접근성·캡처 수명을 유지한다. 화면 전용 조합은 Desktop 내부에서 시작하며 별도 디자인 시스템 구축을 선행하지 않는다.

## 구현 순서와 남은 결정

먼저 합성 데이터로 메인 카드와 상세 A안의 배치·전환을 실제 renderer에서 확인한다. 이어 기존 검색·이름 수정·서버 후보 선택을 연결하고, 선택 캐릭터의 상세 데이터와 별도 창을 연결한다. 마지막으로 실제 Windows 앱의 검색부터 상세 열기·닫기까지 확인한다. 각 단계마다 반드시 별도 PR을 만들 필요는 없다.

장비·서약·강화 표시는 우선 구현할 수 있다. 마법부여 자동 평가와 실제 스킬트리, 서약 종류별 대표 이미지 매핑은 후속 범위다. 아래 결정은 관련 동작을 구현할 때 확인하며 독립적인 화면 작업을 막지 않는다.

- **마법부여 미평가 상태:** 판정 기준을 정하기 전 카드에 안내를 표시할지, 해당 카드를 숨길지 결정이 필요하다. `기타`는 미평가 상태의 대체 값이 아니다.
- **서버 선택 표현:** 초기 요청은 결과 서버별 버튼이었고 현재 메인 시안에는 작은 드롭다운이 남아 있다. 결과 서버만 제공한다는 원칙은 확정이며, 실제 조작 방식은 구현 전 확인한다.
- **이름 입력과 캡처:** 현재 수동 슬롯 검색은 활성 capture 수명에 연결돼 있다. 시안의 대기 화면에서도 독립 검색을 허용할지는 별도 결정이며 기존 수명 검사를 제거해서 맞추지 않는다. 검색 확정 시점과 OCR 복귀 동선도 실제 입력에서 확인한다.
- **상세 창 수명:** 재클릭 시 창 재사용 여부·복수 캐릭터 창 허용·메인 창 종료 때 처리·기존 창에서 다른 캐릭터를 선택했을 때 전환을 정한다. Penpot의 navigate만으로 이 동작이 확정된 것은 아니다.
- **장비 점수:** 시안에는 값이 있지만 검색 응답에는 없다. 상세 응답의 실제 대응 필드·누락 표시를 확인하며 계산식을 추정하지 않는다.

## 구현 완료 확인

- 900·700·500·300px와 중간 폭, 다크·라이트에서 카드와 입력·상세 버튼이 잘리지 않는다. 글꼴과 이미지 실패도 레이아웃을 무너뜨리지 않는다.
- 한 슬롯을 넘겨도 다른 슬롯은 유지된다. 이름·서버·상세 버튼 조작은 면 전환을 일으키지 않는다. 키보드 포커스가 보이고 중첩 버튼이 없다.
- 검색 실패·빈 카드의 비활성 본문과 활성 이름 입력을 구분한다. 로딩·0건·429·네트워크 실패를 기존 검색 상태에 맞게 표시한다.
- 이름·서버 변경 또는 capture 종료 후 늦은 응답이 이전 캐릭터를 복원하지 않는다. 장비와 서약의 부위·색상·칭호·오라·크리쳐가 각 원본 보드와 일치한다.
- 상세 A안의 카드 선택·모션 감소, 창 열기·닫기와 재열기를 실제 Electron에서 확인한다. 실데이터에 예시 마법부여 등급을 표시하지 않는다.

검증 명령은 [scripts 안내](../../scripts/README.md#native-validation)를 따른다. Desktop 변경 시 `pnpm --filter @ldb/desktop test`, `lint`, `build`를 영향 범위에 맞게 실행한다. `build`는 typecheck를 포함한다. 합성 fixture의 시각 확인과 Windows 제품의 캡처·검색·별도 창 성공을 구분해 PR에 기록한다. 이 이관 문서만 변경할 때는 문서 연결·내용·diff를 확인하고 앱 빌드를 반복하지 않는다.
