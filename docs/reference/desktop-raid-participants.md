# 공대원창 검출과 닉네임 크롭

12행 공대 상세 창에서 닉네임 원본 크롭과 행별 영역을 반환하는 공통 함수입니다. `@dfragon/lib`의 파티참가인원 창 검출의 네 고정 슬롯과 달리, 공대원이 나가면 아래 행이 위로 당겨집니다. 행 번호는 한 프레임의 화면 위치이며 캐릭터의 식별자가 아닙니다.

## 범위

- 같은 모양의 12행 공대창을 대상으로 하며 실제 참가자는 12명보다 적을 수 있습니다. 별도 8인 레이드 레이아웃은 포함하지 않습니다.
- 호출자가 게임 client와 기준 이미지를 RGBA로 디코딩해 전달합니다. 함수 내부에서 화면 캡처, 파일 접근, 네트워크 요청이나 앱 상태 변경을 하지 않습니다.
- 닉네임은 OCR을 실행하지 않고 원본 픽셀을 복사합니다. 창을 찾지 못하거나 검출이 모호하면 정상 크롭으로 반환하지 않습니다.
- R/Y/G, 싱글 구분과 수치 열 판독도 객체 반환에 한정합니다. 수치 열은 게임에서 명성과 장비 점수 중 하나로 바꿀 수 있으며, 열 제목으로 종류를 판별합니다. 판독은 쉼표, 소수점, K를 포함한 화면 문자열을 유지하고, 값 범위로 바꾸는 일은 별도 순수 함수가 맡습니다. 판독값을 정답으로 간주하지 않습니다.
- Desktop 일반 화면의 공대 캡처가 이 검출과 닉네임 크롭을 씁니다. Desktop main의 `backend/lib/raid-window.ts`가 기준 헤더(`backend/lib/raid-heading.png`)를 한 번 읽어 제공하며, `backend/capture/raid-frame.ts`가 회차 프레임에서 12행 크롭만 renderer 계약으로 바꿉니다. 다른 창에 가려 투명하게 제외된 픽셀이 있는 행은 읽지 않습니다. 공대 캡처는 수치 열 종류, 수치, 직업명 크롭도 씁니다([공대 캡처 연결](#공대-캡처-연결)). 파티 표식은 공대 캡처에 연결하지 않았습니다.

## 행과 판독값

닉네임 크롭은 참가한 행에서만 반환하며 빈 행도 화면 위치를 유지해 표현합니다. 프레임이 바뀔 때 이전 행의 닉네임이나 메타데이터를 재사용하지 않습니다. R/Y/G, 싱글은 해당 행의 실제 표식을 읽으며 행 번호로 파티를 추정하지 않습니다.

참가 여부와 각 필드의 판독 성공은 별개입니다. 파티 표식이나 점수를 판독하지 못해도 닉네임 크롭을 버리지 않습니다. 점수 원문 `1000.4K`에서 화면에 표시되지 않은 실제 점수를 복원하거나 정답을 추측하지 않습니다.

## 공대창 API와 좌표

`detectDNFRaidParticipantWindow(frame, headingTemplate)`은 `found`일 때 `window`, `scale`, `matchScore`, 수치 열 제목 칸 `valueHeadingRegion`과 12개의 `rows`를 반환합니다. 각 행은 닉네임, 파티 표식, 수치(`equipmentScoreRegion`), 직업명(`jobRegion`) 영역을 가집니다. `cropDNFRaidParticipantNicknames`는 같은 입력에서 각 행의 `nicknameCrop`을 추가합니다. 참가 행의 크롭은 독립 RGBA 복사본이고 빈 행은 `null`입니다. 실패 결과는 기존 파티원창과 같은 `not-found`, `ambiguous`, `search-limit`으로 구분합니다.

두 입력은 `{ width, height, rgba }`이며 `rgba`는 행 우선의 premultiply하지 않은 `Uint8Array | Uint8ClampedArray`입니다. 정확히 `width × height × 4`바이트를 요구하며 원본 alpha를 보존합니다. 게임 client는 양의 정수 크기, 한 변 8192px 이하, 총 33,000,000픽셀 이하를 받습니다. 특정 해상도 일치 조건은 없으며 모든 크기와 팝업 배율을 실제 게임에서 검증한 것은 아닙니다.

기준 헤더는 UI 0%의 `423 × 18` RGBA로, 파티, 레벨, 장비 점수, 캐릭터 이름, 직업명 및 오른쪽 빈 열의 배경과 구분선을 포함합니다. 수치 열 제목이 "명성"인 화면에서도 이 기준 헤더로 창을 찾습니다. 1067×600 표본에서 명성 화면 5장의 `matchScore`는 0.872, 장비 점수 화면 12장은 0.999로, 최종 상관 기준 0.68을 넘었습니다. 그래서 기준 헤더 비교에서 열 제목 영역을 빼지 않았습니다. 호출자가 기준 이미지를 보관, 디코딩하며 라이브러리에 게임 이미지나 플레이어 데이터를 포함하지 않습니다. 입력 크기, 바이트 길이가 잘못됐거나 기준 헤더에 대비가 없으면 `RangeError`를 던집니다.

다음은 헤더 좌상단을 원점으로 한 UI 0% 관측값입니다. 오른쪽, 아래쪽 경계는 포함하지 않습니다.

| 대상 | 기준 좌표 |
| --- | --- |
| 팝업 외곽 | 왼쪽 −15, 위 −68, 오른쪽 450, 아래 324: `465 × 392` |
| 빨간 기준 아이콘 중심 | `(405, −10)` |
| 행 시작 | `y = 18 + 21 × (row − 1)` |
| 닉네임 | `x = 182..268`, `y = 행 시작 + 3..20`: `86 × 17` |
| 파티 표식 | `x = 3..45`, `y = 행 시작 + 2..19`: `42 × 17` |
| 수치(명성 또는 장비 점수) | `x = 106..181`, `y = 행 시작 + 3..20`: `75 × 17` |
| 직업명 | `x = 282..349`, `y = 행 시작 + 3..20`: `67 × 17` |
| 수치 열 제목 | `x = 105..180`, `y = 0..18`: `75 × 18` |

직업명 칸은 역할 배지(D, B, S) 오른쪽의 `眞` 표식부터 돋보기 아이콘 앞까지입니다. 긴 직업명은 줄임표 없이 돋보기 앞에서 글자 중간이 잘리며, 1067×600 표본에서 `데몬슬레이어`는 다섯 글자, `소드마스터`는 네 글자와 잘린 `터`가 보였습니다. 수치 열 제목 칸은 열 제목 글자와 전환 아이콘, 칸 배경을 포함합니다.

닉네임, 파티, 수치, 직업명, 열 제목 사각형은 입력 client 기준 좌표입니다. 배율을 적용한 각 모서리를 기존 파티원창과 같은 ties-to-even 규칙으로 반올림하며, 행 간격을 먼저 반올림해 누적하지 않습니다.

공대창의 `windowBounds`는 사전 필터와 최종 창 사각형이 함께 참조합니다. 각 모서리의 투영은
[`projectParticipantRectangle`](../../packages/lib/src/dnf-participant-regions.ts)을 파티원창과 공유하며,
공대창 고유 외곽, 열, 12행 좌표와 아래 행이 당겨지는 의미는 이 모듈에 유지합니다.

공통 매칭 모듈의 `searchPolicy`는 공대창에도 같은 후보, 프레임 비교 한도와 정밀 탐색을 적용합니다.
0.0025 간격의 배율 후보 21개는 중심 좌우 10단계 반경으로부터 계산합니다. 비교 예산은 앵커마다
갱신하지 않으며, 유효한 창 다음의 앵커에서 예산이 소진되어도 `search-limit`을 반환합니다.

검출은 기존 빨간 연결 영역, 헤더 정규화 상관 함수를 재사용하며 헤더 치수와 아이콘 위치를 공대창에 맞춥니다. 팝업 전체 경계와 12행 구분선으로 후보를 먼저 좁히고 초상화, 레벨, 역할 아이콘 근거로 참가 여부를 판단합니다. 후보 128개와 프레임당 비교 표본 64,000,000개의 기존 탐색 한도를 유지하며, 한도를 넘으면 앞에서 찾은 후보도 부분 성공으로 반환하지 않습니다.

초상화, 레벨, 역할 영역은 공대 레이아웃이 정하며 픽셀 비율과 참가 판정은
[`공통 참가 근거 정책`](../../packages/lib/src/dnf-participant-evidence.ts)을 사용합니다. 밝기, 색상
경계와 세 근거 중 두 개 이상이라는 규칙은 파티원창과 같고, 12행 위치나 행 이동 의미는 공유하지
않습니다. 원본 RGBA와 alpha는 판정에서도 변경하지 않습니다.

## 파티, 수치 판독 API

`readDNFRaidParticipantMetadata(frame, rows, templates)`에 검출 결과의 행과 같은 프레임을 전달하면 행별 `{ row, party, equipmentScoreText }`를 반환합니다. 이름은 장비 점수지만 같은 칸의 명성 표기도 같은 글자 기준으로 읽으며, 어느 값인지는 아래 열 종류 판별로 정합니다. `party`는 `R`, `Y`, `G`, `싱글` 중 하나이며, 각 필드의 미판독과 빈 행은 `null`입니다. 빈 행과 참가 행의 미판독은 원래 행의 `occupied`로 구분합니다. 닉네임 크롭과 판독 결과를 합치는 일은 호출자가 담당합니다.

`DNFRaidMetadataTemplates`는 호출자가 준비하는 다음 기준 이미지입니다. 라이브러리가 기준 데이터를 내려받거나 모델을 학습하지 않습니다.

- `parties`: `{ party, image }` 배열. UI 0%의 표식 영역 전체인 `42 × 17` RGBA를 사용합니다.
- `equipmentScoreGlyphs`: `{ character, image }` 배열. 문자 하나의 폭 1~16, 높이 17 RGBA를 사용하며 `0`~`9`, 쉼표, 소수점, 대문자 `K`를 구분합니다. 문자 전체 획과 점수 영역 안의 세로 위치를 보존해야 하며 가로 여백은 허용합니다.

판독은 필드의 사본을 기준 크기로 맞춰 수행하며 원본을 바꾸지 않습니다. 확대된 필드는 원래 픽셀 중심 위치를 쌍선형으로 표본해 맞춥니다. 파티는 색상과 표식 패턴을 비교하고, 점수는 국소 대비로 글자 획을 분리해 기준 글자와 비교합니다. 기준 이미지, 행 번호, 영역 경계는 검증하며 잘못된 입력은 `RangeError`로 거절합니다. 기준 글자에 없는 문자나 불확실한 필드를 임의의 숫자, 파티로 채우지 않습니다.

[`메타데이터 모듈`](../../packages/lib/src/dnf-raid-metadata.ts)의 `metadataLayout`은 17px 기준 높이,
42px 표식, 75px 점수 폭과 점수 아래 제외 행 2개를 검증, 배열 할당, 정규화, 문자 분리에서 함께
사용합니다. 배지의 `partyPolicy`는 정규화 상관도 0.8 이상과 후보 간 차이 0.06 이상을 요구합니다.
점수의 `scorePolicy`는 국소 대비 55 이상, 문자 획의 교집합/합집합 겹침 점수 0.8 이상과 후보 간
차이 0.08 이상, 최대 16문자를 별도로 정의합니다. 두 0.8은 서로 다른 점수이므로 공유 임계값으로
합치지 않으며 어느 쪽도 판독 성공 확률이 아닙니다. 값, 포함 비교, 표시 문자열은 바꾸지 않습니다.

## 수치 열 종류와 표기 해석 API

[`수치 열 모듈`](../../packages/lib/src/dnf-raid-value-column.ts)이 두 순수 함수를 제공합니다. 화면 캡처, 디코딩, 저장, 네트워크 요청은 하지 않고 프레임을 바꾸지 않습니다.

`classifyDNFRaidValueColumn(frame, valueHeadingRegion, templates)`는 수치 열 제목 칸의 사본을 `75 × 18`로 맞춘 뒤, 호출자가 준비한 UI 0% "명성", "장비 점수" 기준 칸(`templates.fame`, `templates.equipmentScore`)과 회색조 정규화 상관을 비교해 `fame`, `equipment-score`, `unknown`을 반환합니다. 높은 쪽 상관이 0.7 이상이고 두 상관의 차이가 0.15 이상일 때만 종류를 고르고, 아니면 `unknown`입니다. 1067×600 표본 17장에서 같은 종류 기준과의 상관은 1.000, 다른 종류는 0.395였습니다. 확대 화면의 실표본이 없어 기준을 표본값보다 낮게 두었습니다. 기준 칸 크기나 대비, 영역 경계가 잘못되면 `RangeError`를 던집니다.

`parseDNFRaidValueNotation(text)`는 판독 문자열을 그 표기로 보일 수 있는 정수 범위 `{ min, max }`(양 끝 포함)로 바꿉니다.

| 표기 | 결과 |
| --- | --- |
| `12,345`, `2212` | 값 그대로 (`min`과 `max`가 같음) |
| `1000.4K`, `1,000.4K` | 1,000,400 ~ 1,000,499 |
| `1000K` | 1,000,000 ~ 1,000,999 |
| `1.234K` | 1,234 ~ 1,234 |

쉼표는 세 자리 묶음이 온전할 때만 받고, 소수점은 `K`와 함께 소수 세 자리까지만 받습니다. 게임이 `K` 표기에서 보이지 않는 자리를 버린다고 가정한 범위이며, 실제 `K` 표기 화면은 아직 확인하지 못했습니다. 다른 형식이나 안전한 정수 범위를 넘는 값은 추측하지 않고 `null`입니다.

## 검증 자료와 한계

[공대창 합성 테스트](../../packages/lib/test/dnf-raid-participants.test.mjs)는 이동, 배율, 인원 감소, 빈 행, 원본 픽셀 보존, 모호 후보, 잘린 창, 탐색 한도를 확인합니다. [메타데이터 합성 테스트](../../packages/lib/test/dnf-raid-metadata.test.mjs)는 R/Y/G, 싱글, 색상이 다른 점수, 쉼표, 소수점, K, 확대, 미판독, 모호한 기준 이미지, 잘못된 입력을 확인합니다.

실제 화면은 1067×600(검출 배율 1.0)과 1920×1080(검출 배율 1.8) 로컬 표본으로 확인했습니다. 실제 플레이어 데이터와 원본 화면은 저장소, CI에 포함하지 않습니다. 기준 헤더, 표식과 열 제목 기준을 같은 표본에서 추출했으므로 이 확인을 독립 데이터셋의 정확도로 해석하지 않습니다. K 표기의 실제 게임 화면, 1920×1080 명성 열, 다른 client 크기와 배율 조합, 별도 8인 레이드 창, 가림, 게임 UI 변경, Windows DPI 조합, 설치본은 별도 검증 대상입니다.

공대 행 판독의 측정 방법과 표본 결과는 [오프라인 평가](../../apps/desktop/scripts/raid-row-evaluation/README.md)를 따릅니다.

## 공대 캡처 연결

[#760](https://github.com/blahaj94/dfragon/issues/760)에 따라 일반 공대 캡처가 위 판독을 씁니다. 선택 규칙은 [공대 식별 흐름](../rules/character-search.md#desktop의-공대-식별-흐름), 식별 구현은 [Desktop 캐릭터 검색](desktop-character-search.md#카드-직접-조회와-공대-식별)에 있습니다.

- `backend/lib/raid-window.ts`의 `readRaidWindowValues`가 수치 열 제목과 글자 기준 이미지를 한 번 읽어, `classifyDNFRaidValueColumn`으로 열 종류를, `readDNFRaidParticipantValues`로 행별 수치 표기를 읽습니다. `readDNFRaidParticipantValues`는 파티 표식 기준 없이 수치만 읽는 함수이며 수치 판독 규칙은 `readDNFRaidParticipantMetadata`와 같습니다. 파티 표식 기준 이미지는 저장소에 없습니다.
- 수치 판독기는 1920×1080 이하 프레임만 받으므로, 더 큰 프레임은 열 종류만 판별하고 수치는 null입니다.
- `backend/capture/raid-frame.ts`는 행마다 닉네임 크롭, `jobRegion`의 직업명 크롭, 수치 표기를 renderer에 넘깁니다. 직업명 칸에 가려진 픽셀이 있으면 직업명 크롭만 null입니다.
- 직업명 비교 규칙은 `backend/search/raid-job-name.ts`에 있고, 평가 스크립트도 이 파일을 씁니다.

장비 점수 열은 서버 선택에 사용하지 않으며 직업명 그룹 안 최고 명성 후보를 고릅니다. 직업명이 한 후보와만 일치하면 그 후보를 고릅니다.
