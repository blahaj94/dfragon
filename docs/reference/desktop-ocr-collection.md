# Desktop 테스트 OCR 표본 수집

개발 실행과 `alpha` 버전 패키지는 OCR을 실제 실행한 파티 슬롯을 자료실에 자동 수집한다. Stable과 beta 패키지는 이 수집을 끈다. 서버도 `OCR_TEST_UPLOAD_ENABLED=true`가 설정되어야 익명 쓰기를 받으며, 기본값은 비활성이다. 이 설정은 자료실 조회, 라벨 변경이나 모델 접근 권한을 허용하지 않는다.

## 수집 시점과 데이터

- 초기 검색과 Alt+R로 시작한 검색 회차마다 슬롯별 첫 OCR 실행 결과를 한 번 등록한다. 인식 실패도 `prediction: null`로 수집하며 예측 문자열은 검토 전 메타데이터다. 예측을 정답 라벨로 저장하지 않는다.
- 수동 닉네임, 서버 조회만 실행할 때에는 OCR 수집을 추가하지 않는다.
- Alt+Print Screen은 main에서 선택한 창의 새 프레임과 현재 검출된 파티 슬롯을 별도로 수집한다. DNF 또는 DFragon이 활성화된 경우만 단축키를 처리하며 확인창을 띄우지 않는다. 활성 캡처가 없으면 수집하지 않는다.
- 원본 PNG, 기존 학습용 닉네임 좌표, 얼굴과 닉네임을 포함하는 슬롯 문맥 좌표를 함께 전송한다. 닉네임 학습 이미지에 얼굴이나 HP/MP가 섞이지 않도록 두 crop을 구분한다.
- 닉네임 좌표는 같은 원본의 HP/MP 앵커로 main에서 다시 검출한다. 슬롯 문맥은 관측 배율과 해당 앵커에 상대적으로 계산한다. 다른 창에 가려져 픽셀이 지워진 슬롯은 제외한다.

## 프로세스 경계와 실패

Renderer는 `captureId`, main이 발급한 `frameId`, 슬롯 번호와 OCR 예측만 전달한다. URL, 파일 경로, 이미지 바이트, 캡처할 창이나 crop 좌표를 지정할 수 없다. Main은 현재 문서와 캡처 수명을 확인한 뒤 직접 보유한 프레임으로 payload를 만든다.

프레임 보존은 60초, 최대 두 장과 합계 64 MiB로 제한한다. 대기열은 최대 두 장과 64 MiB, 외부 업로드는 한 번에 하나로 제한한다. 자료실 제한인 원본 16 MiB PNG, 8192px 변 길이와 16,777,216 픽셀을 적용한다. 같은 프레임의 아직 전송하지 않은 슬롯은 한 요청으로 합친다.

등록 응답은 대기열 등록만 기다린다. PNG 압축과 전송은 검색 결과와 분리되며, HTTP 요청은 15초 후 종료한다. 실패나 대기열 초과는 정제된 실행 로그로 확인한다. 자동 재시도는 하지 않는다. 따라서 과부하나 연결 실패 시 표본이 누락될 수 있지만 검색은 계속된다. 캡처 종료, 창 변경, 문서 이동이나 앱 종료는 대기열과 진행 요청을 취소한다.

전송 목적지는 `https://ocr.dfragon.com/api/desktop/test-captures`로 고정한다. 쿠키와 토큰을 붙이지 않고 redirect를 거절한다. 서버는 같은 원본과 crop의 재전송을 중복 처리할 수 있으며, 이 경우 이미 저장된 표본 ID를 영수증으로 받는다.

## 검증 범위

합성 HUD로 원본 픽셀 보존, nickname/context 분리, 가려진 얼굴 제외, 회차별 중복 방지와 수동 수집을 검증한다. IPC 테스트는 다른 문서, 종료된 캡처, 외부 이미지 인자와 늦은 프레임 응답이 수집기로 넘어가지 않는지 확인한다.

제공된 실제 스크린샷 8장의 검출 슬롯 29개에서 문맥 사각형이 원본 경계를 벗어나지 않고 닉네임과 얼굴을 모두 포함했다. 연결 중인 스크린샷에서는 준비된 한 슬롯만 검출했다. 실제 Windows 단축키와 배포된 익명 수집 경로의 운영 검증은 별도로 필요하다.
