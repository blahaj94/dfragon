# Desktop MVP 카드 UI

확정 Penpot 디자인의 메인 카드, DFragon 디자인 캔버스의 상세 창과 접근성 요구사항을 정의한다. 기본 앱 진입점은 상단 바, 슬롯 네 개, 테마 전환, 시스템 기본 브라우저로 여는 로그인과 캡처 모달을 사용한다. OCR 식별 IPC의 슬롯 상태와 선택된 캐릭터의 기본 정보를 카드에 연결한다. [Issue #595](https://github.com/blahaj94/dfragon/issues/595)의 창 자동 감지, 첫 후보 검색, 최고 명성 대체 표시와 상시 수동 입력은 구현 PR의 사용자 merge 후 적용한다. 합성 데이터의 상태와 카드 전환 미리보기는 별도 진입점에 유지하며 Windows 실사용 검증과 구분한다.

디자인 원본, 현재 연결 지점, 실행 명령은 [디자인 이관 안내](../reference/desktop-mvp-design-handoff.md)를 참고한다.

## 상단 바

메인 창 맨 위에 폭 전체, 높이 56px의 상단 바를 둔다. 왼쪽부터 로고(마크와 제품 이름), 내비, 게임 연결 상태 칩, 테마, 로그인, 설정 버튼 순서다. 상단 바에는 카메라 버튼과 `Alt`, `R` 키캡을 두지 않는다. 내비는 검색, 캐릭터, 도구, 플래너다. 현재 화면인 검색은 파티와 공대를 고르는 하위 메뉴를 열고 현재 하위 이름을 함께 보인다. 공대를 고르면 파티 카드는 상태를 유지한 채 숨기고 [공대 화면](#공대-화면)으로 바꾼다. 화면이 없는 캐릭터, 도구, 플래너는 누를 수 없음을 알리고 해당 화면을 구현할 때 이 Rule의 변경으로 연결한다. 게임 연결 상태 칩은 캡처 모달과 같은 상태 이름과 tone을 쓰며 모달을 열지 않아도 보인다. 칩은 누를 수 있는 버튼이고 누르거나 키보드 Enter, Space로 캡처 모달을 연다. 접근 가능한 이름은 `화면 캡처, <현재 상태 이름>`이며 키보드 포커스를 신호색 선으로 보이고, 모달을 닫으면 포커스가 칩으로 돌아온다. 칩은 회차를 시작하지 않는다. 칩이 캡처 모달을 여는 유일한 길이므로 창이 좁아도 칩은 숨기지 않고, 공간이 모자라면 제품 이름만 숨긴다. 일반 화면과 개발자 작업 공간이 같은 상단 바를 쓰며, 작업 공간을 여는 동안은 캡처를 멈추므로 내비와 상태 칩을 숨긴다.

메인 창은 1280×800으로 열고 최소 크기는 1024×640이다. 최소 폭에서도 제품 이름만 숨기면 Windows의 OS 창 버튼과 로그인 버튼까지 있는 도구 버튼이 겹치지 않고 카드 네 장이 한 줄에 들어간다. 푸터는 두지 않는다. 캡처 진행 상태는 상단 바의 상태 칩과 캡처 모달이 보이며, 파티 머리에 캡처 진행 문구를 되풀이하지 않는다.

메인 창은 OS 제목 표시줄을 숨기고 OS 기본 창 버튼(최소화, 최대화, 닫기)을 상단 바 안에 그린다. Windows는 오른쪽 끝, macOS는 왼쪽 끝에 OS 버튼이 오며 상단 바 내용은 그 자리를 비운다. 본문을 스크롤해도 상단 바는 창 맨 위에 남고, 대화상자는 OS 창 버튼 띠 아래에 놓는다. 상단 바의 빈 영역을 끌면 창을 옮기고, 버튼과 입력은 끌기 영역에서 뺀다. Windows, Linux에서는 창 버튼의 배경과 기호 색이 현재 테마의 상단 바 색을 따르고, macOS는 OS 기본 색을 쓴다.

## 캡처 모달

상단 바의 게임 연결 상태 칩으로 화면 캡처 모달을 연다. 앱을 시작할 때 창 목록을 조회하고, 던파 후보가 없거나 조회가 실패하면 완료 시점부터 15초 뒤 다시 조회한다. 던파 후보를 찾으면 반복 조회를 멈춘다. 수동 새로고침과 화면 종료는 이전 타이머를 해제하며 늦은 응답을 반영하지 않는다. 진행 중인 자동 조회와 다음 자동 조회를 겹치지 않게 하고, 자동 재조회 실패로 기존 캡처 상태 문구를 덮어쓰지 않는다.

창 목록은 감지된 던파 창을 먼저 표시하고 다른 창도 직접 선택할 수 있다. 앱 시작 시 또는 이후 조회에서 던파 창이 하나만 확인되면 main에 자동으로 등록한다. 직접 선택과 자동 감지는 창 등록만 하며 인식을 시작하지 않는다. 여러 후보 중 하나를 임의로 선택하지 않는다. 사용자가 직접 중지하거나 다른 창을 선택한 뒤 자동 감지가 그 의도를 덮어쓰지 않는다. 연속 선택, 중지, unmount 뒤 늦은 선택 완료를 반영하지 않는다. 다른 창을 고르면 이전 회차와 worker, 검색 수명을 정리하고 새 창만 등록한다. 회차는 창 선택이 아니라 Alt+R이나 파티 머리의 캡처 버튼으로 시작한다.

일반 캡처는 Alt+R 또는 파티 머리의 캡처 버튼을 누를 때마다 한 회차를 시작한다. 공대 화면에서는 Alt+R과 공대 머리의 캡처 버튼이 공대 회차를 시작한다([공대 캡처](#공대-캡처)). 두 입력은 같은 회차 시작 경로를 타며 받는 상태, 거절, 상태 문구와 결과가 같다([Windows 캡처 정책](desktop-windows-capture.md#테스트-버전-자동-캡처와-자료-수집)). 이전 검색, 인식 상태를 비우고 검색 수명을 시작한 뒤 게임 client 영역의 프레임을 한 장만 읽어 네 슬롯의 닉네임, 얼굴 크롭, OCR, 얼굴 비교 검색과 테스트 수집에 사용한다. 개발자 이미지 수집과 같은 HP, MP 검출기로 닉네임을 찾으며 해상도와 UI 배율은 그 회차 프레임에서 검출한다. 가득 찬 HP, MP와 주변 경계가 대상이며 잔량이 줄어든 전투 화면은 지원 범위 밖이다. 회차 프레임을 쓸 수 없거나 파티 프레임이 미검출이면 안내 후 사용자의 다음 회차 시작을 기다린다. 화면이 돌아와도 자동으로 다시 읽거나 인식을 이어가지 않는다. 일부 슬롯만 미검출이면 그 슬롯은 비워 두고 나머지만 같은 프레임으로 처리한다.

회차 진행 중이나 완료 뒤의 Alt+R과 캡처 버튼은 이전 회차를 정리하고 처음부터 다시 실행하며 늦은 이전 결과를 반영하지 않는다. 검색 수명을 시작하는 동안 누른 Alt+R과 캡처 버튼은 무시한다. 처리 뒤에는 다음 회차 시작, 창 변경, 중지 전까지 일반 인식용 프레임을 읽지 않는다. 검색 결과, 재시도와 상세 열기는 보관한 회차의 입력과 결과를 사용하며 수동 입력은 선택한 슬롯만 새로 조회한다. 3초 간격 반복 인식과 인식 간격 설정은 제공하지 않는다. 중지 뒤에는 창을 다시 고른 다음 Alt+R이나 캡처 버튼으로 시작한다.

모달의 닫기, Escape와 로그인 상태 변경은 캡처를 유지한다. 캡처 중지는 별도 버튼으로 처리한다. 상단 바와 모달의 상태 칩은 회차 진행 중 `인식 중`, 완료 뒤 `인식 완료`를 신호색으로 표시하고, `인식 중`은 사각 점 대신 차례로 켜지는 점 세 개를 둔다. 회차 프레임을 쓸 수 없거나 파티 프레임이 없어 안내 후 끝난 회차는 `확인 필요`를 주의 색(`#FFB400`)으로 표시한다. 창 등록 중 `준비 중`은 중립색이고 창 감지 관련 표시는 유지하며, `창 미감지`도 주의 색, `창 감지됨`은 성공 색이다. 창 등록이나 회차 시작, 인식이 실패로 끝나면 창 감지 표시로 덮지 않고 `캡처 실패`를 위험 색으로 표시한다. 공대 화면의 회차 실패도 같다. 실패, 빈 목록은 새로고침, 재선택할 수 있게 한다.

캡처 모달은 DFragon 디자인 캔버스의 캡처 보드(메인 위 캡처 창, 다섯 상태, 창 고르기 목록)를 따른다. 폭 480의 모달 네 모서리 꺾쇠가 상태 색을 따르며(준비 중 중립, 창 감지됨 성공, 인식 중과 인식 완료 신호색, 확인 필요와 창 미감지 주의 색), 인식하는 동안은 꺾쇠가 박자 두 번마다 바깥에서 조여 든다. 높이 64의 머리에 제목, 오른쪽 위를 자른 높이 24 상태 칩, 닫기 버튼을 두고, 그 아래 높이 44의 게임 창 선택 trigger(펼치면 2px 신호색 테두리), 바닥에 `닫기` 보조 버튼과 `캡처 중지` 주 버튼을 둔다. 창을 고르기 전에는 `닫기`만 있다. 캡처 안내 문구는 trigger 아래에 두고, `확인 필요`일 때는 앞에 주의 색, `캡처 실패`일 때는 위험 색 `!` 칸을 붙인다. 파티 머리에 캡처 진행 문구를 두지 않으므로, 모달을 닫은 동안에는 상단 바 옆 화면 밖 알림 영역이 같은 캡처 안내 문구를 보조 기술에 알린다. 모달이 열린 동안에는 바깥 내용이 가려지고 모달 안 안내만 알려 두 번 읽히지 않는다. 창 목록은 그룹 이름, 아이콘 칸과 창 이름, 현재 항목의 왼쪽 2px 막대와 체크, 구분선, `창 목록 새로고침` 순서다. 던파 창이 없어 15초마다 다시 조회하는 동안은 목록 맨 위에 주의 색 `던전앤파이터 찾는 중`과 차례로 켜지는 점 세 개, 그 아래 2px 재조회 진행 막대를 둔다. 진행 막대는 마지막 조회가 끝난 순간부터 다음 자동 조회까지 15초 동안 차오르고, 조회가 끝나 새 목록이 오면 처음부터 다시 찬다. 동작 줄이기 설정에서는 점과 꺾쇠가 멈추고 진행 막대도 목록을 연 순간의 위치에서 멈춘다. 각 카드 중앙의 Process Circle은 OCR부터 캐릭터 확인까지 표시한다. 빈 슬롯에 별도 비활성 상태는 추가하지 않는다.

2026-09-18 요청의 범위는 Windows 제품 캡처와 Mac에서 볼 수 있는 합성 UI 미리보기다. 제품 renderer에 OS 분기를 추가하지 않으며 기존 main 권한 정책은 유지한다. 이 연결 범위는 해당 PR에서 구현, 검증하고 사용자 merge로 활성화한다.

## 메인 화면과 슬롯

디자인 기준은 상단 바 아래 콘텐츠 영역의 네 변 여백 24px, 높이 48px의 파티 머리와 그 아래 간격 16px, 카드 간격 16px다. 카드 네 장은 언제나 한 줄에 놓이고 폭은 창 폭을 따라 변한다. 펼친 카드는 파티 머리 아래 남은 높이를 채운다(1280×800에서 632px, 1024×640에서 472px). 카드 안은 위에서부터 머리(카드 번호, 서버 선택, 서버 순위, 상태 표시, 상세 열기), 그림 칸, 모험단과 길드와 직업, 이름, 스탯 한 줄, 명성과 점수, 면 탭이다. 그림 칸은 280px이고 창이 낮으면 그림 칸이 먼저 줄어든다.

| 창 크기              | 한 줄 카드 수 | 카드 폭 |
| -------------------- | ------------- | ------- |
| 1280 × 800           | 4             | 296px   |
| 1024 × 640(최소)     | 4             | 232px   |
| 1280 × 400(접은 창)  | 4             | 296px   |

최소 폭의 좁은 카드에서는 서버 선택의 글자를 지키려고 서버 순위를 숨긴다. 위 값은 확인할 디자인 표본이며 각 숫자를 breakpoint로 그대로 사용한다는 뜻은 아니다. 중간 폭에서도 줄바꿈, 간격, 가독성이 이어지도록 구현한다. 새로고침이나 다른 슬롯의 조작 때문에 한 슬롯의 카드 면이 바뀌지 않도록 상태를 분리한다.

파티 머리는 DFragon 디자인 캔버스 메인 보드의 배치를 따른다. 왼쪽에 제목 `파티`(24px 700), 캐릭터를 찾은 자리 수(`2/4`처럼 Barlow Condensed 28px, 분모는 흐린 글자)를 두고, 오른쪽에 접기 버튼, 마지막 캡처 시간, 스냅샷 버튼, 캡처 버튼 순서로 둔다. 접기와 스냅샷은 `bg.inset` 면의 48px 정사각형 버튼이고 오른쪽 위를 자른다. 마지막 캡처는 `마지막 캡처` 라벨 아래 마지막으로 인식을 마친 회차의 완료 시각을 `12초 전`처럼 가장 큰 단위 하나(초, 분, 시간, 일)의 상대 시간으로 보이며 숫자는 Barlow Condensed다. 완료한 회차가 없거나 창 변경, 중지로 카드를 비우면 `-`이고, 새 회차가 진행되는 동안은 이전 완료 시각을 유지한다. 상대 시간은 표시 값이 바뀔 때만 다시 그린다. 캡처 버튼은 높이 48의 주 버튼(신호색 면, 오른쪽 위 자름)에 카메라 아이콘, 구분선, `Alt`, `R` 키캡을 두고 접근 가능한 이름은 `파티 캡처, 단축키 Alt R`이다. 누르면 Alt+R과 같은 회차를 시작하며 대화상자를 열지 않는다. Alt+R이 회차를 시작하지 않는 상태에서는 누를 수 없다. 공대 머리에도 같은 모양의 캡처 버튼을 두며 공대 회차를 시작한다([공대 캡처](#공대-캡처)). 접기 버튼은 네 카드를 함께 접고 펼친다. 접힌 카드는 그림 칸, 직업, 스탯 한 줄, 면 탭이 사라지고 머리, 모험단과 길드, 이름, 명성, 점수만 남는다. 사라지는 부분의 높이는 180ms에 줄고 불투명도는 120ms 직선으로 줄어든다. 그림 칸 안의 진행 표시, 안내 문구, 다시 시도 버튼도 접힌 동안 숨으며 펼치면 다시 보인다. 접힌 동안은 캐릭터 면을 보이고 펼치면 고른 면으로 돌아온다. 접을 때는 카드의 상태 전환(180ms)이 끝난 뒤 창 내용 높이를 400px로 줄이고, 펼칠 때는 카드가 펼쳐질 자리를 먼저 만들도록 창을 바로 800px로 늘린다. 동작 줄이기 설정에서는 기다리지 않는다. 연달아 누르면 마지막 상태만 창에 반영한다. 접은 높이는 최소 높이의 예외라 접은 동안 최소 높이를 400px로 낮추고 펼치면 640px로 되돌린다. 최대화, 전체 화면에서는 창 크기를 바꾸지 않으며, 창 높이는 창이 놓인 화면의 작업 영역을 넘지 않는다. 창 높이 요청은 main이 발신 화면과 값(400 이상 800 이하 정수)을 다시 검사한다. 스냅샷 버튼은 모험단 순번 스냅샷을 켜고 끄는 토글이다([모험단 순번 스냅샷](#모험단-순번-스냅샷)). 자리 수 오른쪽에는 캡처 진행 문구를 두지 않으며, 카드의 상세 정보 창을 열지 못했을 때만 그 실패 안내를 보인다.

캐릭터 면에는 그림 칸의 캐릭터 이미지 아래 모험단명과 길드(오른쪽 끝에 직업), 이름 입력, 스탯 한 줄을 배치하고, 명성과 점수는 모든 면의 면 탭 위에 라벨 왼쪽, 값 오른쪽으로 둔다. 검색 응답에 없거나 null인 서버 순위, 길드, 명성, 장비 점수, 모험단, 직업은 0이나 빈칸 대신 `-`로 표시한다. 길드는 상세 응답의 길드 이름을 쓴다. 스탯 한 줄, 장비 점수, 서버 순위와 장비, 기타 면의 값은 main이 넘기는 카드 값(`SelectedCharacterSummary.card`, [Issue #716](https://github.com/blahaj94/dfragon/issues/716)의 공유 계약)에서 오고, 카드 값이 없거나 그 값이 null이면 `-`나 없다는 안내로 보인다. 화면 문자열, 라벨, 접근 가능한 이름은 renderer의 표시 변환 한 곳에서 정하고 IPC로는 숫자와 enum만 받는다.

스탯 한 줄은 공대 카드와 같은 값과 표시 형식이며 라벨만 캔버스 카드 면 보드대로 길게 쓴다(딜러 `공격력 증가`, `공격력 증폭`, `크리티컬`, `스위칭`, 버퍼 `마을 지능`, `30레벨 버프`, `50레벨 버프`, `스위칭`). 역할을 모르면 딜러 라벨에 `-`다. 점수 칸의 라벨은 카드 값의 역할(`role`)을 따라 딜러는 `장비 점수`, 버퍼는 `버프 점수`(2026-10-19 사용자 결정, 값은 엔진의 버프 점수)이고 역할을 모르면 `장비 점수`다. 값이 있는 점수 숫자는 딜러 `score.dealer`(파랑 `#4FA3FF`), 버퍼 `score.buffer`(초록 `#3CC985`)로 칠하고, 역할을 모르거나 값이 없어 `-`로 보일 때는 기본 색이며, 상위, 랭커 카드는 단계 색을 우선한다. 색만으로 역할을 전하지 않도록 라벨(`장비 점수`, `버프 점수`)이 역할을 같이 전하고, 보조 기술 문구도 라벨을 따른다. 점수는 Desktop이 계산한 예측값이라 게임 점수와 1% 안팎 다를 수 있으므로, 화면은 캔버스대로 숫자만 두고 보조 기술과 마우스 설명에 `DFragon 계산값이라 게임 <점수 라벨>와 조금 다를 수 있습니다.`(딜러 `게임 장비 점수와`, 버퍼 `게임 버프 점수와`)를 전한다. 엔진이 계산하지 못한 점수는 `-`이고 보조 기술에 `계산하지 못함, <사유 종류>`(장비 정보 부족, 아이템을 판별하지 못함, 입력값이 게임 스탯과 다름, 계산 오류, 그 밖은 계산 제외)를 전하며 엔진의 원문 메시지는 보이지 않는다. 서버 순위는 `#18240`처럼 보이고 보조 기술에 `서버 순위 18240위, DFragon이 수집한 캐릭터 N명 기준`으로 전체 유저 순위가 아님을 알린다.

장비 면과 기타 면은 그림 칸과 소속 자리에 맨 위 이름(18 700)과 직업 한 줄을 두고 그 아래를 채운다. 머리의 서버 선택과 상세 열기는 어느 면에서나 같은 자리에 남고, 이름 입력은 캐릭터 면에만 둔다. 장비나 기타 면에서 서버를 바꾸면 새 조회가 시작되어 조회하는 동안 캐릭터 면의 진행 표시를 보이고, 결과가 오면 고른 면으로 돌아온다. 장비 면은 세트 섹션과 서약 섹션이다. 세트는 대표 장비 그림, 세트 이름(세트 희귀도 색), 세트 포인트, 무기와 세트 부위(방어구 다섯, 장신구 셋, 특수 장비 셋)의 희귀도 격자, 희귀도 개수를 보인다. 서약은 서약 그림, 세트 옵션 이름(없으면 세트 이름, 서약 이름), 묵언의 진의 9칸 목록, 서약 세트 포인트, 서약 본체와 결정 11칸의 희귀도 격자, 결정 희귀도 개수를 보인다. 묵언의 진의 칸은 연 단계를 칠하고 접근 가능한 이름을 `N단계 <옵션명>`, 빈 칸은 `N단계 비어 있음`으로 둔다. 격자는 희귀도 개수가 글자로 전하므로 보조 기술에서 뺀다. 세트나 서약이 없으면 `세트 정보 없음`, `서약 정보 없음`과 `-` 포인트, 빈 격자로 보인다.

기타 면은 무기, 상의, 머리어깨, 하의, 벨트, 신발, 목걸이, 팔찌, 반지, 보조장비, 마법석, 귀걸이 12행에 장비 아이콘 칸, 아이템 이름(희귀도 색, 보조 기술에는 `부위, 아이템 이름`), 강화는 `gameEnhance`, 증폭은 `gameAmplify` 색의 `+N`(보조 기술에는 `강화 N`, `증폭 N`), 마법부여 등급 3점 표시를 둔다. 3점은 종결 셋, 준종결 둘, 기타 하나를 등급 색으로 칠하고 접근 가능한 이름은 `마법부여 종결`, `마법부여 준종결`, `마법부여 기타`다. 판정 기준표에 없는 마법부여는 미평가 `-`(보조 기술 `마법부여 미평가`)이며 `기타`로 바꾸지 않는다. 장비 면과 기타 면이 카드 높이를 넘으면 면 안에서 스크롤하고 카드 크기는 바뀌지 않는다. 아이콘 칸은 24 × 24에 희귀도 색의 1px 테두리, 아래 2px 바와 아래에서 올라오는 옅은 면을 두고 그 안에 22 × 22 아이콘을 그린다. 태초 칸은 은은한 빛과 주기마다 지나가는 빛줄기를 더하고 동작 줄이기 설정에서는 빛줄기를 그리지 않는다. 아이콘은 장식이라 대체 문구를 비우고 부위와 이름은 이름 칸이 전한다. 장착하지 않은 부위나 그림을 불러오지 못한 행은 같은 크기의 빈 칸만 남겨 줄이 밀리지 않는다. 아이템 그림은 검증한 `itemId`로 renderer가 만든 `https://img-api.neople.co.kr/df/items/<itemId>`이고, 세트와 서약 그림은 실패하면 같은 크기의 대체 표시를 둔다. 장비 아이콘 위 강화, 증폭 숫자와 마법부여 마름모는 최종안에서 제거된 그대로이고, 2026-10-19 캔버스 갱신으로 기타 면 행 왼쪽에 아이콘 칸만 다시 들어왔다.

카드 상태는 테두리 대신 네 모서리 꺾쇠의 색으로 보이며 상태 이름을 글자로 다시 쓰지 않는다. 검색 실패의 노란색 `#FFD54A`는 2026-10-20 담당자 요청으로 빨간 표시를 바꾼 것이며, 그림 칸은 기본 격자 그대로이고 빨간 빗금은 스냅샷에 없는 모험단에만 쓴다. 결과 0건은 실패와 같은 모양에 `검색 결과가 없습니다` 문구를 두어 통신 오류, 호출 제한의 안내와 구분한다. 보조 기술에는 우측 상단 표시의 접근 가능한 이름과 카드의 알림 영역으로 상태를 전한다. 이름 입력에 들어가거나 고치는 동안이 이름 수정 중이며, 조회를 확정하면 해당 검색 상태로 돌아간다.

면은 카드 아래의 면 탭(캐릭터, 장비, 기타)으로 고르고, 조회를 마친 카드는 세 탭을 모두 누를 수 있다. 입력, 서버 선택, 상세 버튼 조작은 카드 면을 넘기지 않는다. 카드 안에 버튼이나 입력을 중첩하지 않고 면 탭, 이름 입력, 서버 선택, 상세 버튼을 형제 요소로 두어 키보드로도 각각 접근할 수 있게 한다. 면 탭은 화살표로 포커스를 옮기고 Enter, Space나 누름으로 고른다. 상세 아이콘은 호버뿐 아니라 키보드 포커스로도 드러나며, 호버가 없는 환경에서도 사용할 수 있어야 한다.

이름과 서버는 캡처 여부와 관계없이 항상 수정할 수 있다. Enter 또는 서버 변경으로 지정한 서버와 닉네임을 조회한다. 수동 검색은 캡처와 독립된 검색 수명에서 실행하며 이전 OCR 응답이 수동 선택을 덮어쓰지 않는다. 수동 조회 자체는 OCR이나 자료 업로드를 실행하지 않는다.

디자인의 빈 카드는 API의 검색 결과 0건과 같은 뜻이 아니다. 기존 `SearchSlot.state`의 `idle`, `pending`, `success`, `empty`, `failure`를 유지하고 0건, 통신 오류와 호출 제한을 구분한다. 서버 선택은 지원하는 전체 서버를 제공한다. OCR은 두 번 연속 같은 입력을 기다리지 않고 회차 프레임 한 장의 첫 후보로 확정한다. 첫 후보는 앞뒤 공백만 제거하며 두 번째 후보로 보정하지 않는다. 쓸 수 없는 첫 후보는 조회 실패로 표시하고 이유와 모델 원문은 renderer DevTools Console에만 표시한다. 첫 후보의 검색 결과가 없어도 조회 실패를 표시하며 두 번째 후보로 넘어가지 않는다.

이름의 검색 결과가 있으면 명성 내림차순으로 외형을 확인한다. 명성 null은 마지막이며 처음 비교 기준을 통과한 캐릭터를 선택한다. 외형을 확인할 수 없거나 모두 불일치하면 가장 명성이 높은 후보를 표시하고 외형으로 확정한 결과와 구분해 안내한다. 명성 0과 null을 구분하고 알 수 없는 값은 `-`로 표시한다. 숫자를 세어 올리는 표시는 값이 있을 때만 쓴다. 후보 조회와 상세 조회 자체의 통신 오류를 조회 성공으로 바꾸지 않는다.

2026-10-19 담당자 결정([Issue #716](https://github.com/blahaj94/dfragon/issues/716))으로 면을 DFragon 디자인 캔버스 카드 면 보드의 세 면(캐릭터, 장비, 기타)으로 바꾸고 세 면을 모두 활성화하며, 구현 PR의 사용자 merge 후 적용한다. 그 전에는 면 탭이 캐릭터, 장비, 서약, 투자 현황 네 면이었고 제품은 기본 정보 면만 연결해 다른 면을 누를 수 없게 두었으며, 합성 미리보기만 네 면을 비교했다. 이전 서약 면의 서약 슬롯은 장비 면의 서약 섹션으로, 투자 현황 면의 12부위 목록은 기타 면으로 옮겼다. main이 카드 값을 넘기기 전에도 세 면을 고를 수 있고 각 면은 `-`와 없다는 안내를 보이며, 값을 만들어 넣지 않는다. 실패는 정제된 오류를 표시하며 Alt+R 또는 수동 입력으로 새 조회를 시작한다. 이미지 CSP와 고정 네오플 origin 정책은 유지한다.

### 상위, 랭커 단계

상위와 랭커 단계는 UI 셸과 합성 데이터까지가 범위다. 단계를 나누는 기준(명성, 장비 점수, 서버 순위)과 데이터 연결은 별도 과제이며, 제품 카드는 단계 데이터를 받지 않아 단계를 보이지 않는다. 단계는 조회를 마친 카드에만 보이고 이름 수정 중, 검색 실패, 결과 0건, 대기 표시가 단계보다 앞선다.

| 단계 | 꺾쇠와 움직임 | 카드 표시 |
| ---- | ------------- | --------- |
| 상위 | `tier.top` 꺾쇠가 4초 주기로 밝아졌다 흐려진다. 옅은 금색 빛줄기가 주기마다 한 번 카드를 지나간다 | 카드 번호 칩 면, 서버 순위 테두리와 글자, 명성과 점수 값, 그림 칸 아래 2px 선이 `tier.top` |
| 랭커 | `tier.ranker` 꺾쇠가 주기 시작에 바깥 10px에서 조여 든다. 옅은 청록 빛줄기가 지나가고 카드에 4px 간격 스캔선을 깐다 | 면 `tier.rankerSurface`, 외곽선 1px `tier.rankerOutline`, 그림 칸 `tier.rankerWell`. 카드 번호 칩 면, 오른쪽 위를 자른 서버 순위 면, 명성과 점수 값, 그림 칸 아래 2px 선이 `tier.ranker` |

빛줄기는 주기의 6%에서 30% 사이에 지나가고 나머지 시간은 멈춘다. 동작 줄이기 설정에서는 빛줄기를 그리지 않고 꺾쇠 움직임을 멈추며 색과 스캔선으로 단계를 보인다. 단계 이름은 화면 글자로 쓰지 않고 보조 기술에 `상위 단계`, `랭커 단계`로 전한다.

### 공대 화면

2026-10-19 사용자 결정으로 공대 화면을 DFragon 디자인 캔버스의 `공대 화면, 12명` 보드대로 다시 그리며 구현 PR의 사용자 merge 후 적용한다. 검색 하위 메뉴의 공대는 네 명씩 세 파티, 12자리를 한 보드에 보인다. 보드는 왼쪽 32 폭의 파티 라벨 열(`1파티`, `2파티`, `3파티`, 숫자는 Barlow Condensed 28 700, 오른쪽 2px 선)과 축약 카드 네 열, 세 줄이고 거터는 12다. 콘텐츠 위 여백은 20, 머리(높이 48)와 보드 사이는 12다. 카드는 1280×800에서 12장이 스크롤 없이 들어가는 크기(288×205.33, 접으면 288×125.33)로 창 크기와 상관없이 고정하며, 창이 이보다 좁거나 낮으면 머리는 고정하고 보드 영역만 가로와 세로로 스크롤한다(1024×640에서도 카드 크기는 같다). 스크롤 막대는 8px `border.strong`이고 오른쪽 콘텐츠 여백 안에 둔다. 파티 화면의 카드는 지금처럼 창 크기를 따라 줄어든다.

공대 카드는 파티 카드를 줄인 축약 카드다. 위에서부터 머리(높이 36. 카드 번호 칩, 서버 선택, 서버 순위나 상태 표시, 상세 열기), 그림 칸 72와 그 오른쪽의 모험단과 길드, 이름, 직업, 스탯 한 줄, 명성과 점수 바닥이다. 면 탭은 없다. 상태는 파티 카드와 같은 꺾쇠(기본, 이름 수정 중, 검색 실패와 결과 0건, 빈 카드와 인식 대기의 점선)와 상위, 랭커 단계로 보이며, 상위, 랭커는 카드 번호 칩, 서버 순위, 그림 칸 아래 선, 명성 값을 단계 색으로 그리고, 점수 값은 단계와 상관없이 역할 색으로 그린다. 스탯 한 줄은 딜러가 공격력 증가, 증폭, 크리티컬, 스위칭 레벨, 버퍼가 마을 지능, 30레벨과 50레벨 버프 수치, 스위칭 레벨이다. 값과 점수, 서버 순위는 파티 카드와 같은 카드 값에서 오고(2026-10-19, Issue #716), 카드 값이 없거나 역할을 모르면 딜러 라벨에 `-`로 보이며, 역할을 아는 값이 오면 그 역할의 라벨을 쓴다. 점수 라벨과 색, 점수와 서버 순위의 보조 기술 문구는 파티 카드와 같다. 실패, 결과 0건, 최고 명성 대체 표시(`외형 미확인, 최고 명성 후보입니다.`)와 입력 안내는 스탯 한 줄 자리에 세 줄까지 보이고, 안내가 있는 동안은 스탯 한 줄을 숨긴다. 조회 중과 공대 캡처의 인식 중에는 그림 칸 가운데에 진행 표시를 둔다. 응답에 없는 값은 파티 카드처럼 `-`로 보인다.

파티 카드처럼 이름 칸에 입력하고 서버를 고르면 그 자리만 조회하며, 빈 자리도 이름 입력과 서버 선택부터 시작한다. 실패와 결과 0건 안내는 Alt+R로 다시 인식하거나 서버와 이름을 직접 조회하도록 알린다. 12자리는 서로 독립된 조회 상태를 가진다. 공대 조회는 파티 카드의 수동 조회와 다른 검색 수명을 써서 파티 네 자리와 공대 12자리가 서로를 덮어쓰지 않는다. 한 자리를 다시 조회하면 그 자리의 이전 요청을 취소하고 늦은 결과를 반영하지 않으며 다른 자리의 요청은 유지한다. Main은 공대 조회의 자리 번호(0 이상 11 이하 정수)와 입력을 다시 검사한다. 파티와 공대 화면을 오가도 두 화면의 입력과 조회 결과는 유지된다. 공개 검색의 호출 제한(최근 60초 10회)은 파티와 공대 조회가 함께 쓰므로, 12자리를 짧은 시간에 채우면 일부 자리에 호출 제한 안내가 보일 수 있다.

카드를 끌어 다른 카드에 놓으면 두 자리를 맞바꾼다. 놓을 자리는 카드 안쪽 2px 신호색 선, 끄는 카드는 흐리게 보인다. 키보드로는 카드(접근 가능한 이름 `n번 자리, 끌어서 옮기기`)에 포커스한 채 Alt와 방향키로 위, 아래 파티나 같은 파티의 왼쪽, 오른쪽 자리와 맞바꾸며, 옮긴 카드에 포커스가 남아 이어서 옮길 수 있다. 카드 안의 이름 칸과 버튼은 방향키를 그대로 쓴다. 실제로 맞바꿨을 때만 보조 기술에 `n번 자리와 m번 자리를 맞바꿨습니다.`를 알리며 같은 두 자리를 다시 맞바꿔도 다시 알린다. 자리마다 속한 파티와 키보드 조작은 설명으로 전한다. 끄는 동안 회차가 바뀌거나 배치가 바뀌거나 맞바꿀 수 없게 되면 그 끌기는 끝나며, 다른 앱에서 끌어 온 글자나 파일은 자리 맞바꾸기로 받지 않는다. 맞바꾸기는 화면 자리에 놓인 검색 슬롯만 바꾸므로 그 자리의 입력, 검색 상태와 결과, 진행 중 조회와 늦은 응답, 상세 열기가 카드와 함께 옮겨 가고 main 공대 검색의 자리 번호 계약은 바뀌지 않는다. 공대 캡처가 인식하는 동안(검색 수명 시작부터 이름 인식을 마치거나 회차가 끝날 때까지)은 끌기와 키보드 맞바꾸기를 받지 않고 이름에서 `끌어서 옮기기`를 뺀다. 회차는 12자리를 비우고 게임 화면의 행 순서대로 1~12번 자리를 채우므로 시작할 때 배치를 처음으로 되돌린다.

머리는 파티 머리와 같은 배치다. 왼쪽에 제목 `공대`, 캐릭터를 찾은 자리 수(`10/12`처럼 Barlow Condensed 28px, 분모는 흐린 글자)와 실패 안내를, 오른쪽에 16 간격으로 접기 버튼, 마지막 캡처, 스냅샷 버튼, 캡처 버튼을 둔다. 접기와 스냅샷은 파티 머리와 같은 48px 정사각형 버튼이고, 스냅샷은 파티와 같은 토글이며 스냅샷을 따로 가진다([모험단 순번 스냅샷](#모험단-순번-스냅샷)). 머리의 안내는 검색 연결 실패와 상세 정보 창 열기 실패만 보이고, `캡처 대기`나 공대 회차 진행 문구는 두지 않는다([공대 캡처](#공대-캡처)).

### 공대 캡처

2026-10-19 사용자 요청으로 공대 화면의 Alt+R 캡처를 이번 범위로 채택하며 구현 PR의 사용자 merge 후 적용한다. 공대 화면을 보는 동안 Alt+R과 공대 머리의 캡처 버튼은 공대 회차를 시작하고 파티 회차는 시작하지 않는다. 캡처 버튼은 파티 머리와 같은 높이 48의 주 버튼(카메라 아이콘, 구분선, `Alt`, `R` 키캡)이고 접근 가능한 이름은 `공대 캡처, 단축키 Alt R`이다. 누르면 Alt+R과 같은 회차를 시작하며 대화상자를 열지 않는다. 창 등록 전, 등록 중, 등록 실패, 공대 검색 수명을 시작하는 동안, 중지 뒤처럼 Alt+R이 공대 회차를 시작하지 않는 상태에서는 누를 수 없다. 마지막 캡처는 파티와 같은 방식으로 마지막으로 인식을 마친 공대 회차의 완료 시각을 보이며, 진행 중 공대 회차가 창 변경이나 중지로 끝나면 `-`가 된다.

회차는 12자리를 비우고 게임 화면의 12행 공대 상세 창에서 공대원 이름을 읽어 화면 순서대로 1~12번 자리에 넣고, 이름을 읽은 자리마다 조회를 시작한다([Windows 캡처 정책](desktop-windows-capture.md#windows-제품-캡처-정책)). 공대 상세 창에는 서버가 없어 지금은 같은 이름의 후보 중 최고 명성 캐릭터를 대체 표시하며(2026-10-19 사용자 결정), 서버와 이름은 카드에서 고쳐 다시 조회할 수 있다. 공대 창의 명성이나 장비 점수를 이용한 근사 매칭은 후속 과제다. 인식하는 동안 카드는 진행 표시를 보이고 읽은 이름을 이름 칸에 둔다. 회차가 진행되는 동안 사용자가 서버와 이름으로 조회한 자리는 그 회차의 늦은 인식 결과로 덮지 않는다. 진행 문구는 파티 캡처와 같은 단계를 쓴다(`공대를 인식하고 있습니다.`, `인식을 마쳤습니다. 다시 인식하려면 Alt+R을 누르세요.`). 공대 상세 창을 찾지 못하거나 창이 둘 이상이거나 공대원 이름을 찾지 못하면, 게임 창이 가려졌거나 읽을 수 없으면 Alt+R 전에 확인할 내용을 알리고 회차를 끝낸다. 글자 인식과 검색 시작 실패도 안내 후 Alt+R로 다시 시작할 수 있다. 공대 화면을 보는 동안 상단 바 상태 칩과 캡처 모달은 창이 등록돼 있으면 공대 회차의 상태(`인식 중`, `인식 완료`, `확인 필요`, `캡처 실패`)와 문구를, 창 등록 전과 등록 실패, 중지 뒤에는 창 선택 상태를 보인다. 공대 머리도 파티 머리와 같은 기준으로 `캡처 대기`와 공대 회차 진행 문구를 두지 않고, 검색 연결 실패나 상세 정보 창 열기 실패처럼 캡처 진행이 아닌 안내만 보인다. 공대 회차 문구는 상단 바의 화면 밖 캡처 안내 하나가 보조 기술에 알려, 공대 머리와 두 번 읽히지 않는다.

접기는 파티와 같은 상태를 쓰고 파티와 공대 사이를 오가도 유지된다. 접은 창 높이는 보이는 화면을 따라 파티 400, 공대 560이며, 접은 채 화면을 바꾸면 그 화면의 높이로 바로 맞추되, 접는 카드 전환(180ms)이 아직 끝나지 않았으면 남은 시간 뒤에 맞춘다. 접은 동안 최소 높이는 그 접은 높이로 낮추고 펼치면 640으로 되돌린다. 접힌 공대 카드는 그림 칸, 직업, 스탯 한 줄과 안내를 숨기고 머리, 모험단과 길드, 이름, 명성, 점수만 남겨 560 창에서 12장이 스크롤 없이 들어간다. 창 높이 요청은 파티와 같이 main이 발신 화면과 값(400 이상 800 이하 정수)을 다시 검사한다.

### 모험단 순번 스냅샷

2026-10-20 담당자 요청([Issue #731](https://github.com/blahaj94/dfragon/issues/731))으로 파티와 공대 머리의 스냅샷 버튼을 켜는 토글로 채택하며 구현 PR의 사용자 merge 후 적용한다. 사람은 모험단으로 구분하므로 같은 사람이 다른 캐릭터로 바꿔 들어와도 같은 모험단이면 같은 사람이다.

- 켜기: 버튼을 누르는 순간 지금 캐릭터를 찾은 자리의 모험단명을 자리마다 저장한다. 빈 자리, 검색 실패와 결과 0건 자리, 모험단 조회가 실패해 모험단명이 없는 자리는 저장하지 않는다.
- 자리가 바뀐 카드: 다시 캡처하거나 조회한 뒤 스냅샷 때와 자리가 다른 카드에만 서버 칩 뒤에 `스냅샷 순번 N` 칩(파티 1~4, 공대 1~12)을 보인다. 같은 자리면 칩이 없다. 카드를 자동으로 옮기지 않는다. 공대는 화면 자리 기준이라 카드를 맞바꾸면 칩이 생긴다.
- 스냅샷에 없는 모험단: 카드 전체를 빨간 빗금과 안쪽 2px 빨간 선으로 덮고 머리에 빨간 `!` 칩(`스냅샷에 없는 모험단`)을 보인다. 덮는 층은 클릭을 막지 않고 보조 기술에서 숨긴다. 빈 자리를 포함해 스냅샷의 모험단 밖의 모험단이 어느 자리에 보여도 같다.
- 같은 모험단의 캐릭터가 둘 이상: 지금 자리에 스냅샷과 같은 모험단이 있으면 그 자리를 먼저 맞추고, 남은 캐릭터에 스냅샷의 자리를 자리 순서대로 배정한다. 스냅샷보다 많이 들어온 캐릭터는 스냅샷에 없는 모험단으로 본다. 모험단명이 없는 카드는 칩과 경고를 모두 보이지 않는다. 이 둘과 검색 실패 자리를 스냅샷에서 빼는 것은 시안과 디자인 문서의 판단이며 담당자가 다르게 정하면 따른다.
- 끄기: 켜진 버튼을 누르면 버튼 아래에 `스냅샷을 지우시겠습니까?` 확인(`role="alertdialog"`, `취소`와 `지우기`)을 열고, `취소`에 먼저 포커스한다. `지우기`만 스냅샷을 지우고 칩과 경고를 걷는다. Escape와 바깥 누름은 스냅샷을 지우지 않는다.
- 접근성: 버튼은 켜짐을 `aria-pressed`로 전하고 이름 `파티 모험단 순번 스냅샷`, `공대 모험단 순번 스냅샷`은 켜고 꺼도 바뀌지 않는다. 칩은 `role="img"`와 이름으로 상태를 색만으로 전하지 않는다. 칩과 덮는 층은 전환 없이 바로 나타나고 사라지며, 토글 버튼의 색 전환은 동작 줄이기에서 0이다.
- 회차 번호: 스냅샷이 켜진 동안 파티와 공대 머리의 인원수(`2/4`, `10/12`) 바로 오른쪽 같은 줄에 `#1`, `#2`처럼 몇 번째 회차인지 보인다. Barlow Condensed 28px 700, 신호색(다크는 크림 `#F8E8C8`), `line-height` 1이며 `#`도 숫자와 같은 크기다. 스냅샷을 켠 순간이 `#1`이고, 켜 둔 동안 캡처 버튼이나 Alt+R로 회차를 시작하는 순간 하나 오른다. 인식을 마치기 전에 시작만 해도 세며 실패하거나 취소된 회차도 한 회차다. 받아들이지 않은 시작(창이 없거나 수명 시작을 기다리는 중)과 창 선택, 중지는 세지 않는다. 스냅샷을 끄면(확인 뒤) 번호가 사라지고 다시 켜면 `#1`부터다. 파티와 공대가 따로 센다. 접근 가능한 이름은 `N번째 파티`, `N번째 공대`(`role="img"`)다.
- 수명: 스냅샷과 회차 번호는 renderer 메모리에만 두고 IPC, 디스크, 저장소에 남기지 않아 앱을 끄면 사라진다. 파티와 공대는 따로 가지며 한쪽을 지워도 다른 쪽은 그대로다.

## 상세 창

2026-10-20 담당자 요청으로 상세 창을 DFragon 디자인 캔버스 `제안 · 상세 창` 보드의 다크 카드 패널로 바꾸며, 구현 PR의 사용자 merge 후 적용한다. 그 전에는 1280×800(최소 1024×640) 보조 창의 높이 56 상단 바 아래에 제품은 캐릭터 카드와 기본 정보 패널을, 합성 미리보기는 장비, 서약, 강화, 마법부여, 스킬트리 카드 다섯 장을 겹친 카드 더미(상세 A안)를 두었다.

- **창:** 내용 크기는 보드의 패널과 같은 540 × 650이다. 폭은 고정이고, 낮은 화면을 위해 높이는 480까지 줄일 수 있다(작업자가 정함). 최대화와 전체 화면은 없다. OS 제목줄과 창 버튼 없이 창 전체가 카드 면이고, 카드 면은 라이트 모드에서도 다크라 테마를 정하지 않고 다크 값으로 그린다. 머리의 빈 곳을 끌면 창을 옮기고, 머리 오른쪽 `닫기` 버튼으로 닫는다.
- **머리(높이 40):** 서버 칩, 서버 순위, 남는 공간, 조회 시각, 닫기 버튼 순서다. 서버 순위는 메인 카드와 같은 값과 보조 기술 이름이다. 조회 시각은 창을 연 정보의 마지막 조회를 `12초 전`처럼 가장 큰 단위 하나의 상대 시간으로 보이고, 마우스 설명에 날짜와 시각을 둔다. 이 창에서는 정보를 새로 조회하지 않는다.
- **캐릭터 칸:** 112 × 120 그림 칸 오른쪽에 모험단과 길드, 이름(24 700, 화면의 `h1`)과 전직, 명성과 점수(Barlow Condensed 32 700)를 둔다. 없는 모험단, 길드, 전직, 명성, 점수는 `-`이고 명성 0과 구분한다. 점수의 라벨(`장비 점수`, 버퍼는 `버프 점수`)과 색, 마우스 설명과 보조 기술은 메인 카드의 점수 칸과 같다.
- **탭:** 장비와 스킬 두 탭이고, 탭 아래 내용만 스크롤하며 창 크기는 바뀌지 않는다.
- **장비 탭:** 왼쪽은 세트 머리(그림 32, 세트 희귀도 색의 이름, 세트 포인트)와 장비 12줄이다. 줄은 무기, 방어구 다섯(머리어깨, 상의, 하의, 벨트, 신발), 장신구 셋(팔찌, 목걸이, 반지), 특수 장비 셋(보조장비, 마법석, 귀걸이) 묶음으로 띄운다. 오른쪽은 서약 머리(그림, 메인 카드 장비 면과 같은 서약 이름, 서약 포인트, 그 아래 묵언의 진의 9칸)와 서약 본체, 결정 0~2번, 3~10번 묶음의 12줄이다. 세트나 서약이 없으면 `세트 정보 없음`, `서약 정보 없음`과 `-` 포인트이고 서약 목록은 비운다.
- **장비 줄:** 최소 높이 40에 28 × 28 아이콘 칸(오른쪽 위를 8 자르고 태초는 메인 카드 기타 면과 같은 빛), 아이템 이름(13 500, 희귀도 색, 보조 기술에는 `부위, 아이템 이름`)과 마법부여 옵션 한 줄, 오른쪽에 강화(`gameEnhance`)나 증폭(`gameAmplify`)의 `+N`(보조 기술 `강화 N`, `증폭 N`)을 둔다. 서약 본체와 결정 줄에는 `+N`이 없다. 마법부여 옵션은 카드 값의 옵션 이름과 수치를 ` · `로 잇고 줄이거나 묶지 않는다. 보드의 옵션 줄 11px은 카드 면 최소 글자 크기 12px로 올린다. 줄에 마우스를 올리거나 키보드로 포커스하면 설명 상자를 연다. 장착 정보가 없는 줄은 `-`와 같은 크기의 빈 칸만 두고 포커스와 설명 상자가 없다.
- **설명 상자:** 보드 순서대로 아이템 이름과 `+N`, `부위 · 희귀도`, 아이템 설명, 마법부여 옵션, 버프 스킬 줄, 플레이버 문구를 둔다. 아이템 설명(`itemExplain`)은 카드 글자색이고 첫 줄이 `[용을 베는 자]`처럼 `[`로 시작해 `]`로 끝나면 그 줄을 신호색(`cardSignal`)으로 강조한다. 버프 스킬 줄(`itemBuff.explain`)은 흐린 글자색(`cardFgMuted`), 플레이버 문구(`itemFlavorText`)는 더 흐린 글자색(`cardFgSubtle`)이다. 세 문구는 원문 줄바꿈을 지키고 줄이거나 고치지 않는다. 문구가 비었거나 아이템 상세를 받지 못한 아이템(`itemDetail.status`가 `unavailable`)은 그 칸을 두지 않는다. 2026-10-20 담당자 요청으로 더하며 구현 PR의 사용자 merge 후 적용한다.
- **묵언의 진의:** 연 단계를 칠하고, 칸에 마우스를 올리거나 포커스하면 `N단계 <옵션명>`(빈 칸은 `N단계 비어 있음`)을 보인다. 보드의 옵션별 칸 색은 정한 규칙이 없어 한 색으로 칠한다.
- **스킬 탭:** 스킬 그림의 출처, 습득하지 않은 스킬을 포함한 직업 전체 스킬 목록과 칸 배치가 정해지지 않아 `스킬 정보는 아직 연결하지 않았습니다.`만 둔다.
- **이 범위에서 그리지 않는 것:** 보드 장비 이름 옆의 색 막대(성위 부여, 융합 표시), 마법부여 옵션 줄임말(`모속강`, `물마독`), 유일 장비 빛([Issue #726](https://github.com/blahaj94/dfragon/issues/726)), 마법부여 등급([Issue #728](https://github.com/blahaj94/dfragon/issues/728))은 그리지 않으며 값을 추정해 넣지 않는다.
- **값의 출처:** main이 선택 결과의 상세 응답에서 기본 정보, 길드와 조회 시각을, 검색이 메인 카드에 넘긴 카드 값(`CharacterCard`, 점수 포함)을 그대로 담아 넘기고 점수를 다시 계산하지 않는다. 설명 상자 문구는 main이 같은 상세 응답의 장비 12부위와 서약 본체, 결정 0~10번에 붙은 아이템 상세(`itemDetail.data`)에서 itemId별로 골라 넘긴다. 화면 문자열은 renderer의 표시 변환에서 정한다.

## 표현과 이미지

- 라이트 메인 보드도 캐릭터 카드 면은 다크 색상을 유지하며 바깥 배경과 상단 바를 밝게 바꾼다.
- 글꼴은 번들한 Pretendard이며 한국어 줄바꿈과 표기 기준은 [글꼴과 한국어 타이포그래피](design-system.md#글꼴과-한국어-타이포그래피)를 따른다. 메인 카드의 기타 면 목록은 캔버스 카드 면 보드대로 머리 12px, 행 높이 30에 위쪽 `card.divider` 선, 아이템 이름 13px 500, 강화와 증폭 Barlow Condensed 22px 700이다(2026-10-19, 이전에는 2026-09-19 Typo 적용 요청의 `Typo.caption` 12px/18px 교차 행 목록). 상세 창의 장비 목록은 [상세 창](#상세-창)대로 최소 높이 40 줄에 아이템 이름 13px 500, 마법부여 옵션 12px, 강화와 증폭 Barlow Condensed 18px 700이다. 카드 면의 라벨과 단위도 최소 글자 크기 12px를 지킨다.
- 무료 아이콘의 디자인 원본은 [Lucide 아이콘 목록](https://lucide.dev/icons)이다. 현재 사용 중인 moon, camera, chevron-down, chevron-right, check, monitor, refresh-cw, user, external-link를 기준으로 구현 자산과 출처를 맞추고, 선 끝과 꺾임은 각지게(`stroke-linecap="square"`, `stroke-linejoin="miter"`) 그린다. 설정(조절 막대), 테마(마름모 해), 대기(각진 모래시계), 접기, 스냅샷은 dfragon-design [아이콘](https://github.com/blahaj94/dfragon-design/blob/main/design/icons.md)의 DFragon 아이콘을 쓴다.
- 캐릭터 이미지: `https://img-api.neople.co.kr/df/servers/<serverId>/characters/<characterId>?zoom=<zoom>`.
- 아이템 이미지: `https://img-api.neople.co.kr/df/items/<itemId>`.
- 세트와 서약 그림은 카드 값의 세트 대표 장비, 서약 itemId로 만든 아이템 이미지다. 이전 합성 미리보기의 임시 서약 그림은 2026-10-20 상세 창 변경에서 지웠다.

장비 슬롯은 반지름 없는 면에 아래 2px 바의 희귀도 색으로 등급을 보인다.

| 장비 희귀도 | 색상        | 장비 희귀도 | 색상        |
| ----------- | ----------- | ----------- | ----------- |
| 커먼        | `#FFFFFF`   | 언커먼      | `#68D5ED`   |
| 레어        | `#B36BFF`   | 유니크      | `#FF00FF`   |
| 에픽        | `#FFB400`   | 레전더리    | `#FF7800`   |
| 크로니클    | `#FF6666`   | 태초        | `#50E3C2`   |

마법부여 표시색은 종결 `#50E3C2`, 준종결 `#FFB400`, 기타 `#FFFFFF`다. 메인 카드는 3점의 칠한 개수와 등급 이름(접근 가능한 이름)을 함께 표시하며 색만으로 판정 결과를 전달하지 않는다. 상세 창은 등급을 아직 표시하지 않는다. **판정 기준이 없는 실제 데이터를 `기타`로 간주하거나 디자인의 예시 등급을 실사용 캐릭터에 복사하지 않는다.**

이미지 로딩은 HTTPS `https://img-api.neople.co.kr`와 `https://bbscdn.df.nexon.com` 두 고정 origin만 허용한다. 실데이터 연결 구현에서 renderer CSP의 `img-src`에 이 origin만 추가하고 기존 `self`, `data:`를 유지한다. `*`, 임의 origin, renderer fetch, Neople API key를 추가하지 않는다. URL은 검증한 식별자와 고정 base로 구성하고 외부 데이터의 임의 URL을 그대로 사용하지 않는다. 네트워크 오류, 누락, 이미지 decode 실패에는 같은 크기의 대체 표시를 둔다. 합성 미리보기는 출처를 기록한 로컬 자산을 사용하며 제품 CSP의 원격 허용을 선행하지 않는다.

## 후속 연결에서 남은 결정

실제 스킬트리와 서약 종류별 대표 이미지 매핑은 후속 범위다. 마법부여 등급 판정은 API의 기준표가 맡는다(Issue #716 2번 항목). 아래 결정은 관련 동작을 구현할 때 확인하며 독립적인 화면 작업을 막지 않는다.

- **마법부여 미평가 상태:** 메인 카드의 기타 면은 기준표에 없는 등급을 `-`와 보조 기술 `마법부여 미평가`로 보인다(2026-10-19). 상세 창 장비 줄에 등급을 더할 때 같은 표시를 쓸지 정한다. `기타`는 미평가 상태의 대체 값이 아니다.
- **상세 창 수명:** 상세 창은 캐릭터별로 열고 같은 캐릭터는 재사용한다. 메인 창을 실제로 닫으면 상세 창을 함께 닫는다. 스킬 탭은 후속 범위다.
- **장비 점수:** Desktop main의 점수 엔진이 계산해 카드 값에 담고(Issue #716 3번 항목), renderer는 계산식을 추정하지 않는다. 엔진이 없거나 계산하지 못하면 `-`다. 예측값 표시는 위 캐릭터 면 설명대로 보조 기술과 마우스 설명에만 두며, 화면에 보일 표시가 필요하면 디자인 결정(blahaj94/dfragon-design#40)으로 바꾼다. 서버 순위는 API가 수집 범위에서 센 명성 순위다.

## 구현 완료 확인

- 1280 × 800, 최소 1024 × 640, 접은 높이 400과 그 사이 크기, 다크, 라이트에서 파티 카드와 입력, 상세 버튼, 파티와 공대 머리의 캡처 버튼이 잘리지 않고, 1280×800 보드 크기로 고정한 공대 카드 12장은 1280×800과 접은 1280×560에서 스크롤 없이 보이고 그보다 작은 창에서는 보드 영역의 가로, 세로 스크롤로 모두 닿는다. 공대 카드는 끌기와 Alt 방향키로 자리를 맞바꾼다. 글꼴과 이미지 실패도 레이아웃을 무너뜨리지 않는다.
- 한 슬롯을 넘겨도 다른 슬롯은 유지된다. 이름, 서버, 상세 버튼 조작은 면 전환을 일으키지 않는다. 키보드 포커스가 보이고 중첩 버튼이 없다.
- 캡처 여부와 무관하게 이름과 서버를 수정할 수 있다. 카드 중앙의 진행 표시, 0건, 최고 명성 대체 표시, 429와 네트워크 실패를 구분한다.
- 이름, 서버 변경 또는 capture 종료 후 늦은 응답이 이전 캐릭터를 복원하지 않는다. 장비와 서약의 부위, 색상, 칭호, 오라, 크리쳐가 각 원본 보드와 일치한다.
- 상세 창의 머리 끌기와 닫기 버튼, 탭 전환, 장비 줄의 설명 상자, 창 열기, 닫기와 재열기를 실제 Electron에서 확인한다. 실데이터에 예시 마법부여 등급을 표시하지 않는다.

검증 명령은 [scripts 안내](../../scripts/README.md#native-validation)를 따른다. Desktop 변경 시 `pnpm --filter @dfragon/desktop test`, `lint`, `build`를 영향 범위에 맞게 실행한다. `build`는 typecheck를 포함한다. 합성 fixture의 시각 확인과 Windows 제품의 캡처, 검색, 별도 창 성공을 구분해 PR에 기록한다. 이 이관 문서만 변경할 때는 문서 연결, 내용, diff를 확인하고 앱 빌드를 반복하지 않는다.
