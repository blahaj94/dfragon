# Desktop MVP 카드 UI

확정 Penpot 디자인의 메인 카드와 접근성 요구사항을 정의한다. 기본 앱 진입점은 상단 바, 슬롯 네 개와 캡처 창을 사용한다. 2026-10-27 축소 시안([Issue #808](https://github.com/blahaj94/dfragon/issues/808))으로 창을 세로로 줄이고 다크 테마로 고정했다. 로그인, 설정, 개발자 도구, 캐릭터 상세 창과 카드의 장비, 기타 면은 두지 않는다(2026-10-26 결정, [Issue #796](https://github.com/blahaj94/dfragon/issues/796)). OCR 식별 IPC의 슬롯 상태와 선택된 캐릭터의 기본 정보를 카드에 연결한다. 창 자동 감지, 첫 후보 검색, 최고 명성 대체 표시와 상시 수동 입력을 제공한다([Issue #595](https://github.com/blahaj94/dfragon/issues/595)). 합성 데이터의 상태와 카드 전환 미리보기는 별도 진입점에 유지하며 Windows 실사용 검증과 구분한다.

디자인 원본, 현재 연결 지점, 실행 명령은 [디자인 이관 안내](../reference/desktop-mvp-design-handoff.md)를 참고한다.

## 상단 바

메인 창 맨 위에 폭 전체, 높이 44px의 상단 바를 한 줄로 둔다. 왼쪽부터 로고(마크와 제품 이름), 검색 메뉴, 보이는 화면의 머리(제목, 인원수, 회차), 빈 공간, 마지막 캡처, 스냅샷 버튼, 캡처 버튼, 새 버전 칩(있을 때), 게임 연결 상태 칩, OS 창 버튼 순서다. 파티 머리와 공대 머리는 카드 위에 따로 줄을 두지 않고 상단 바 안에 그리며, 보이는 화면의 머리만 그린다. 테마 버튼은 두지 않는다. 검색 메뉴는 파티와 공대를 고르는 하위 메뉴를 열고 현재 하위 이름을 함께 보인다. 공대를 고르면 파티 카드는 상태를 유지한 채 숨기고 [공대 화면](#공대-화면)으로 바꾼다. 게임 연결 상태 칩은 캡처 창과 같은 상태 이름과 tone을 쓰며 캡처 창을 열지 않아도 보인다. 칩은 누를 수 있는 버튼이고 누르거나 키보드 Enter, Space로 캡처 창을 연다. 접근 가능한 이름은 `화면 캡처, <현재 상태 이름>`이며 키보드 포커스를 신호색 선으로 보이고, 캡처 창을 닫으면 포커스가 칩으로 돌아온다. 칩은 회차를 시작하지 않는다. 칩이 캡처 창을 여는 유일한 길이므로 창이 좁아도 칩은 숨기지 않고, 공간이 모자라면 제품 이름만 숨긴다.

새 버전이 있으면 게임 연결 상태 칩 왼쪽에 `새 버전 v1.2.0`처럼 버전을 단 칩을 둔다. 칩을 누르면 `Release 열기`와 `닫기`가 있는 작은 메뉴가 뜬다. 닫으면 앱을 다시 시작할 때까지 같은 버전을 다시 알리지 않는다. 카드 위에 알림 줄을 두지 않으며, 알림이 있어도 창 높이는 바뀌지 않는다.

메인 창의 내용 높이는 보이는 화면을 따라 파티 163px, 공대 300px이고 폭은 1280px로 연다. 앱은 파티 화면 높이로 열리고, 검색 메뉴로 화면을 바꿀 때마다 그 화면의 높이로 창을 맞춘다. 사용자가 바꾼 폭은 유지하고, 사용자가 키운 높이는 화면을 바꾸면 그 화면의 높이로 돌아간다. 최대화, 전체 화면에서는 창 크기를 바꾸지 않으며, 창 높이는 창이 놓인 화면의 작업 영역을 넘지 않는다. 창 높이 요청은 main이 발신 화면과 값(163 이상 300 이하 정수)을 다시 검사한다. 최소 크기는 1024×163이다. 최소 폭에서도 제품 이름만 숨기면 Windows의 OS 창 버튼과 도구 버튼이 겹치지 않고 카드 네 장이 한 줄에 들어간다. 창이 1280보다 넓으면 카드가 늘어난다. 푸터는 두지 않는다. 캡처 진행 상태는 상단 바의 상태 칩과 캡처 창이 보이며, 파티 머리에 캡처 진행 문구를 되풀이하지 않는다.

메인 창은 OS 제목 표시줄을 숨기고 OS 기본 창 버튼(최소화, 최대화, 닫기)을 상단 바 안에 상단 바 높이 44로 그린다. Windows는 오른쪽 끝, macOS는 왼쪽 끝에 OS 버튼이 오며 상단 바 내용은 그 자리를 비운다. 본문을 스크롤해도 상단 바는 창 맨 위에 남고, 대화상자는 OS 창 버튼 띠 아래에 놓는다. 상단 바의 빈 영역을 끌면 창을 옮기고, 버튼과 입력은 끌기 영역에서 뺀다. Windows, Linux에서는 창 버튼의 배경과 기호 색이 다크 상단 바 색을 따르고, macOS는 OS 기본 색을 쓴다.

## 캡처 창

상단 바의 게임 연결 상태 칩으로 화면 캡처 창을 연다. 앱을 시작할 때 창 목록을 조회하고, 던파 후보가 없거나 조회가 실패하면 완료 시점부터 15초 뒤 다시 조회한다. 던파 후보를 찾으면 반복 조회를 멈춘다. 수동 새로고침과 화면 종료는 이전 타이머를 해제하며 늦은 응답을 반영하지 않는다. 진행 중인 자동 조회와 다음 자동 조회를 겹치지 않게 하고, 자동 재조회 실패로 기존 캡처 상태 문구를 덮어쓰지 않는다.

창 목록은 감지된 던파 창을 먼저 표시하고 다른 창도 직접 선택할 수 있다. 앱 시작 시 또는 이후 조회에서 던파 창이 하나만 확인되면 main에 자동으로 등록한다. 직접 선택과 자동 감지는 창 등록만 하며 인식을 시작하지 않는다. 여러 후보 중 하나를 임의로 선택하지 않는다. 사용자가 직접 중지하거나 다른 창을 선택한 뒤 자동 감지가 그 의도를 덮어쓰지 않는다. 연속 선택, 중지, unmount 뒤 늦은 선택 완료를 반영하지 않는다. 다른 창을 고르면 이전 회차와 worker, 검색 수명을 정리하고 새 창만 등록한다. 회차는 창 선택이 아니라 Alt+R이나 파티 머리의 캡처 버튼으로 시작한다.

일반 캡처는 Alt+R 또는 파티 머리의 캡처 버튼을 누를 때마다 한 회차를 시작한다. 공대 화면에서는 Alt+R과 공대 머리의 캡처 버튼이 공대 회차를 시작한다([공대 캡처](#공대-캡처)). 두 입력은 같은 회차 시작 경로를 타며 받는 상태, 거절, 상태 문구와 결과가 같다([Windows 캡처 정책](desktop-windows-capture.md#자동-창-등록과-회차-시작)). 이전 검색, 인식 상태를 비우고 검색 수명을 시작한 뒤 게임 client 영역의 프레임을 한 장만 읽어 네 슬롯의 닉네임, 얼굴 크롭, OCR, 얼굴 비교 검색에 사용한다. HP, MP 검출기로 닉네임을 찾으며 해상도와 UI 배율은 그 회차 프레임에서 검출한다. 가득 찬 HP, MP와 주변 경계가 대상이며 잔량이 줄어든 전투 화면은 지원 범위 밖이다. 회차 프레임을 쓸 수 없거나 파티 프레임이 미검출이면 안내 후 사용자의 다음 회차 시작을 기다린다. 화면이 돌아와도 자동으로 다시 읽거나 인식을 이어가지 않는다. 일부 슬롯만 미검출이면 그 슬롯은 비워 두고 나머지만 같은 프레임으로 처리한다.

회차 진행 중이나 완료 뒤의 Alt+R과 캡처 버튼은 이전 회차를 정리하고 처음부터 다시 실행하며 늦은 이전 결과를 반영하지 않는다. 검색 수명을 시작하는 동안 누른 Alt+R과 캡처 버튼은 무시한다. 처리 뒤에는 다음 회차 시작, 창 변경, 중지 전까지 일반 인식용 프레임을 읽지 않는다. 검색 결과와 재시도는 보관한 회차의 입력과 결과를 사용하며 수동 입력은 선택한 슬롯만 새로 조회한다. 3초 간격 반복 인식과 인식 간격 설정은 제공하지 않는다. 중지 뒤에는 창을 다시 고른 다음 Alt+R이나 캡처 버튼으로 시작한다.

캡처 창의 닫기 X와 Escape는 캡처를 유지한다. 캡처 중지는 별도 버튼으로 처리한다. 상단 바와 캡처 창의 상태 칩은 회차 진행 중 `인식 중`, 완료 뒤 `인식 완료`를 신호색으로 표시하고, `인식 중`은 사각 점 대신 차례로 켜지는 점 세 개를 둔다. 회차 프레임을 쓸 수 없거나 파티 프레임이 없어 안내 후 끝난 회차는 `확인 필요`를 주의 색(`#FFB400`)으로 표시한다. 창 등록 중 `준비 중`은 중립색이고 창 감지 관련 표시는 유지하며, `창 미감지`도 주의 색, `창 감지됨`은 성공 색이다. 창 등록이나 회차 시작, 인식이 실패로 끝나면 창 감지 표시로 덮지 않고 `캡처 실패`를 위험 색으로 표시한다. 공대 화면의 회차 실패도 같다. 실패, 빈 목록은 새로고침, 재선택할 수 있게 한다.

캡처 창은 DFragon 디자인 캔버스 축소 시안의 캡처 창 보드를 따른다. 163 창에는 세로 대화상자와 아래로 펼치는 목록이 들어가지 않으므로, 게임 연결 상태 칩 아래 오른쪽 정렬로 760×104 가로 패널을 띄우고 상단 바 아래 내용은 어둡게 덮는다. 패널 네 모서리 꺾쇠가 상태 색을 따르며(준비 중 중립, 창 감지됨 성공, 인식 중과 인식 완료 신호색, 확인 필요와 창 미감지 주의 색, 캡처 실패 위험 색), 인식하는 동안은 꺾쇠가 박자 두 번마다 바깥에서 조여 든다. 머리 줄은 제목 `화면 캡처`, 오른쪽 위를 자른 상태 칩, 캡처 안내, 빈 공간, `캡처 중지`(주 버튼, 창을 고른 동안만), `새로고침`(회색 보조 버튼, 오른쪽 위 자름), 닫기 X 순서다. 아래쪽 `닫기` 버튼은 두지 않는다. 캡처 안내는 상태 칩 오른쪽에 한 줄로 두고, `확인 필요`일 때는 앞에 주의 색, `캡처 실패`일 때는 위험 색 `!` 칸을 붙인다. 안내가 길면 말줄임하고 전체 문구는 `title`과 보조 기술 알림으로 전하므로, 안내가 있어도 패널 높이는 104로 같다. 파티 머리에 캡처 진행 문구를 두지 않으므로, 캡처 창을 닫은 동안에는 상단 바 옆 화면 밖 알림 영역이 같은 캡처 안내 문구를 보조 기술에 알린다. 캡처 창이 열린 동안에는 바깥 내용이 가려지고 캡처 창 안 안내만 알려 두 번 읽히지 않는다.

캡처 창 본문의 창 목록은 radio 타일 한 줄이다. 타일은 최대 220 폭, 높이 44이고 창 이름과 그룹(`감지된 게임`, `다른 창`)을 두 줄로 쓰며, 고른 창은 크림 왼쪽 선과 체크로 보인다. 타일이 패널 폭에 다 들어가지 않으면 가로로 넘긴다. 던파 창이 없어 15초마다 다시 조회하는 동안은 맨 앞에 점선 타일(주의 색 `던전앤파이터 찾는 중`, 차례로 켜지는 점 세 개, 2px 재조회 진행 막대)을 두고, 목록 조회 실패면 실패 타일을 둔다. 진행 막대는 마지막 조회가 끝난 순간부터 다음 자동 조회까지 15초 동안 차오르고, 조회가 끝나 새 목록이 오면 처음부터 다시 찬다. 창 목록 새로고침은 머리 줄의 `새로고침` 버튼이 맡는다. 동작 줄이기 설정에서는 점과 꺾쇠가 멈추고 진행 막대도 캡처 창을 연 순간의 위치에서 멈춘다. 각 카드의 진행 표시는 OCR부터 캐릭터 확인까지 표시한다. 빈 슬롯에 별도 비활성 상태는 추가하지 않는다.

2026-09-18 요청의 범위는 Windows 제품 캡처와 Mac에서 볼 수 있는 합성 UI 미리보기다. 제품 renderer에 OS 분기를 추가하지 않으며 기존 main 권한 정책은 유지한다.

## 메인 화면과 슬롯

디자인 기준은 상단 바 아래 콘텐츠 영역의 위아래 여백 12px, 좌우 여백 16px, 카드 간격 16px다. 카드 네 장은 언제나 한 줄에 놓이고 폭은 창 폭을 따라 변하며, 카드는 콘텐츠 영역의 남은 높이를 채운다. 카드 안 여백은 위 8, 좌우 10, 아래 8이다. 썸네일은 72×72로 카드 위 끝부터 왼쪽 열을 차지하고, 오른쪽 열은 위에서부터 이름 칸, `모험단 | 길드`, 명성과 점수 한 줄, 넷째 줄이며 줄 사이는 4다.

| 창 크기 | 한 줄 카드 수 | 카드 폭 |
| --- | --- | --- |
| 1280 × 163(파티) | 4 | 300px |
| 1024 × 163(최소) | 4 | 236px |

위 값은 확인할 디자인 표본이며 각 숫자를 breakpoint로 그대로 사용한다는 뜻은 아니다. 중간 폭에서도 줄바꿈, 간격, 가독성이 이어지도록 구현한다. 새로고침이나 다른 슬롯의 조작 때문에 한 슬롯의 카드 상태가 바뀌지 않도록 상태를 분리한다.

파티 머리는 상단 바 안의 한 줄이다(DFragon 디자인 캔버스 축소 시안). 왼쪽에 제목 `파티`(12px), 캐릭터를 찾은 자리 수(`2/4`처럼 Barlow Condensed 16px, 분모는 흐린 글자)를 두고, 오른쪽에 마지막 캡처, 스냅샷 버튼, 캡처 버튼 순서로 둔다. 세 컨트롤의 높이는 28이다. 스냅샷 버튼은 28 정사각형이고 오른쪽 위를 자른다. 마지막 캡처는 `마지막 캡처 12초 전`을 한 줄로 두고, 마지막으로 인식을 마친 회차의 완료 시각을 가장 큰 단위 하나(초, 분, 시간, 일)의 상대 시간으로 보이며 숫자는 Barlow Condensed다. 완료한 회차가 없거나 창 변경, 중지로 카드를 비우면 `-`이고, 새 회차가 진행되는 동안은 이전 완료 시각을 유지한다. 상대 시간은 표시 값이 바뀔 때만 다시 그린다. 캡처 버튼은 주 버튼(신호색 면, 오른쪽 위 자름)에 카메라 아이콘과 `Alt R` 글자만 두고, `캡처` 글자와 키 테두리는 두지 않는다. 접근 가능한 이름은 `파티 캡처, 단축키 Alt R`이다. 누르면 Alt+R과 같은 회차를 시작하며 대화상자를 열지 않는다. Alt+R이 회차를 시작하지 않는 상태에서는 누를 수 없다. 공대 머리에도 같은 모양의 캡처 버튼을 두며 공대 회차를 시작한다([공대 캡처](#공대-캡처)). 스냅샷 버튼은 모험단 순번 스냅샷을 켜고 끄는 토글이다([모험단 순번 스냅샷](#모험단-순번-스냅샷)). 자리 수 오른쪽에는 캡처 진행 문구를 두지 않는다. 머리 안내는 상단 바 한 줄에서 길면 말줄임하고 전체 문구는 `title`과 보조 기술 알림으로 전한다. 공대 머리는 검색 연결을 확인하지 못했을 때만 그 안내를 보인다. 창이 이미 작아 카드 접기는 두지 않는다(2026-10-27, [Issue #824](https://github.com/blahaj94/dfragon/issues/824)).

카드는 캐릭터 면 하나다. 이름 칸(높이 20)은 이름 입력과 서버 선택을 테두리 하나로 감싸고, 서버 선택은 칸 안 오른쪽의 높이 16 칩이다. 이름 칸은 오른쪽 열 첫 줄의 남는 폭을 채우고, 같은 줄 오른쪽 끝에 상태 표시(이름 수정 중 점 3개, 실패 `!`), [후보 칩](#후보-창), 스냅샷 순번 칩을 둔다. 파티 카드에는 자리 번호와 대기 모래시계를 두지 않는다. 이름 칸에는 placeholder를 두지 않고 숨은 label(`n번 캐릭터 이름`)로 이름을 전한다. 둘째 줄은 모험단명과 길드를 1px 세로선으로 나눈다. 찾지 못한 자리는 그 자리에 안내 문구(예: `캐릭터를 찾지 못했습니다`)를, 안내가 없으면 흐린 `모험단`을 둔다. 셋째 줄은 `명성 125,850 | 장비 414,806`처럼 라벨과 값을 한 줄에 두는 명성과 점수다. 넷째 줄은 찾은 카드면 직업(`眞 ` 없이)과 안내, 검색 실패면 `다시 시도` 버튼이다. 면 탭, 스탯 한 줄, 서버 순위, 상세 열기 버튼은 두지 않는다. 검색 응답에 없거나 null인 길드, 명성, 장비 점수, 모험단, 직업은 0이나 빈칸 대신 `-`로 표시하고, 명성과 점수의 `-`는 흐린 색이다. 길드는 상세 응답의 길드 이름을 쓴다. 장비 점수와 점수 라벨의 역할은 main이 넘기는 카드 값(`SelectedCharacterSummary.card`, [Issue #716](https://github.com/blahaj94/dfragon/issues/716)의 공유 계약)에서 오고, 카드 값이 없거나 그 값이 null이면 `-`로 보인다. 화면 문자열, 라벨, 접근 가능한 이름은 renderer의 표시 변환 한 곳에서 정하고 IPC로는 숫자와 enum만 받는다.

점수 라벨은 카드 값의 역할(`role`)을 따라 딜러는 `장비 점수`, 버퍼는 `버프 점수`(2026-10-19 사용자 결정, 값은 엔진의 버프 점수)이고 역할을 모르면 `장비 점수`다. 화면에는 두 글자(`장비`, `버프`)로 줄여 보인다. 명성은 기본 글자색이고, 값이 있는 점수는 라벨과 값을 함께 딜러 `score.dealer`(파랑 `#4FA3FF`), 버퍼 `score.buffer`(초록 `#3CC985`)로 칠한다. 역할을 모르거나 값이 없어 `-`로 보일 때는 기본 색이며, 상위, 랭커 카드는 명성과 점수 모두 단계 색을 우선한다. 카드 안의 명성, 점수 숫자는 한글과 같은 12px 글꼴이고 세어 올리지 않는다. 색만으로 역할을 전하지 않도록 라벨(`장비 점수`, `버프 점수`)이 역할을 같이 전하고, 보조 기술 문구도 라벨을 따른다. 엔진이 낸 점수는 Desktop이 계산한 예측값이라 게임 점수와 1% 안팎 다를 수 있으므로, 화면은 캔버스대로 숫자만 두고 보조 기술과 마우스 설명에 `DFragon 계산값이라 게임 <점수 라벨>와 조금 다를 수 있습니다.`(딜러 `게임 장비 점수와`, 버퍼 `게임 버프 점수와`)를 전한다. 엔진이 계산하지 못한 점수는 `-`이고 보조 기술에 `계산하지 못함, <사유 종류>`(장비 정보 부족, 아이템을 판별하지 못함, 입력값이 게임 스탯과 다름, 계산 오류, 그 밖은 계산 제외)를 전하며 엔진의 원문 메시지는 보이지 않는다. 엔진이 장비 점수 계산을 건너뛰고 근사값을 냈으면 `-` 대신 근사값을 `≈12,345`처럼 `≈`를 붙여 같은 역할 색으로 보이고, 보조 기술과 마우스 설명에 `근사값, <사유 종류>. <근사 방법>이라 게임 <점수 라벨>와 1% 넘게 다를 수 있습니다.`를 전한다([Issue #784](https://github.com/blahaj94/dfragon/issues/784)). 근사 방법은 엔진의 출처(`approximate_source`)를 따라 `이전 시즌 융합석을 빼고 계산한 값`, `이전 시즌 융합석을 빼고 입력값 차이를 무시하고 계산한 값`, `입력값 차이를 무시하고 계산한 값`, `공통 스킬 레벨을 1로 두고 계산한 값`, 그 밖은 `정확히 계산하지 못한 추정값`이다. 엔진의 경고 문구(`warning`)는 원문 메시지를 담으므로 보이지 않는다.

| 상태 | 카드 표시 | 이름 칸 |
| --- | --- | --- |
| 조회 완료, 캐릭터 선택됨 | 회색 꺾쇠 | 투명 테두리, 수정 가능 |
| 이름 수정 중, 후보 미리보기 중 | 신호색 꺾쇠, 머리 줄 오른쪽 네모 점 3개 | 크림 테두리, 수정, 검색 확정 가능 |
| 검색 실패, 결과 0건 | 노란 꺾쇠(`#FFD54A`), 머리 줄 오른쪽 노란 `!` 칸 | 노란 테두리, 수정 가능 |
| 활성 capture 안의 인식 대기 | 꺾쇠 없는 점선 카드. 공대 카드만 머리 줄 끝에 각진 모래시계 | 회색 테두리, 직접 입력 가능 |
| 빈 카드 | 꺾쇠 없는 점선 카드, 호버 반응 없음 | 회색 점선 테두리, 직접 입력 가능 |

카드 상태는 테두리 대신 네 모서리 꺾쇠의 색으로 보이며 상태 이름을 글자로 다시 쓰지 않는다. 검색 실패의 노란색 `#FFD54A`는 2026-10-20 담당자 요청으로 빨간 표시를 바꾼 것이며, 썸네일은 기본 격자 그대로이고 빨간 빗금은 스냅샷에 없는 모험단에만 쓴다. 결과 0건은 실패와 같은 모양에 `검색 결과가 없습니다` 문구를 두어 통신 오류, 호출 제한의 안내와 구분한다. 보조 기술에는 우측 상단 표시의 접근 가능한 이름과 카드의 알림 영역으로 상태를 전한다. 이름 입력에 들어가거나 고치는 동안이 이름 수정 중이며, 조회를 확정하면 해당 검색 상태로 돌아간다.

카드 안에 버튼이나 입력을 중첩하지 않고 이름 입력, 서버 선택, 후보 칩과 다시 시도 버튼을 형제 요소로 두어 키보드로도 각각 접근할 수 있게 한다.

이름과 서버는 캡처 여부와 관계없이 항상 수정할 수 있다. Enter 또는 서버 변경으로 지정한 서버와 닉네임을 조회한다. 파티 카드와 공대 카드 모두 이름 칸에서 Tab을 누르면 다음 요소로 넘어가지 않고 칸 안 서버 목록을 연다. Shift+Tab과 한글 조합 중의 Tab은 그대로 둔다. 목록에서 방향키로 고르고 Enter를 누르면 지금 서버와 같아도 그 서버로 바로 조회하고, Escape로 닫으면 조회하지 않는다. 목록이 닫히면 포커스는 서버 칩으로 가서 다음 Tab은 다음 요소로 넘어간다. 수동 검색은 캡처와 독립된 검색 수명에서 실행하며 이전 OCR 응답이 수동 선택을 덮어쓰지 않는다. 수동 조회 자체는 OCR이나 자료 업로드를 실행하지 않는다.

디자인의 빈 카드는 API의 검색 결과 0건과 같은 뜻이 아니다. 기존 `SearchSlot.state`의 `idle`, `pending`, `success`, `empty`, `failure`를 유지하고 0건, 통신 오류와 호출 제한을 구분한다. 서버 선택은 지원하는 전체 서버를 제공한다. OCR은 두 번 연속 같은 입력을 기다리지 않고 회차 프레임 한 장의 첫 후보로 확정한다. 첫 후보는 앞뒤 공백만 제거하며 두 번째 후보로 보정하지 않는다. 쓸 수 없는 첫 후보는 조회 실패로 표시하고 이유와 모델 원문은 renderer DevTools Console에만 표시한다. 첫 후보의 검색 결과가 없어도 조회 실패를 표시하며 두 번째 후보로 넘어가지 않는다.

이름의 검색 결과가 있으면 명성 내림차순으로 정렬하고 명성 null은 마지막에 둔다. 상위 후보 전원의 얼굴을 비교해 가장 가까운 후보가 거리 상한과 2위와의 차이 기준을 모두 만족하면 선택한다. 후보가 한 명이거나 얼굴, 이미지가 없거나 기준을 만족하지 못하면 가장 명성이 높은 후보를 표시하고 얼굴로 확정한 결과와 구분해 안내한다. 명성 0과 null을 구분하고 알 수 없는 값은 `-`로 표시한다. 숫자를 세어 올리는 표시는 값이 있을 때만 쓴다. 후보 조회와 상세 조회 자체의 통신 오류를 조회 성공으로 바꾸지 않는다.

2026-10-26 결정([Issue #796](https://github.com/blahaj94/dfragon/issues/796))으로 카드의 장비, 기타 면과 면 탭을 지우고 캐릭터 면만 남겼다. main이 카드 값을 넘기기 전에는 점수를 `-`로 보이며 값을 만들어 넣지 않는다. 실패는 정제된 오류를 표시하며 Alt+R 또는 수동 입력으로 새 조회를 시작한다. 이미지 CSP와 고정 네오플 origin 정책은 유지한다.

### 후보 창

얼굴로 확정하지 못한 파티 카드는 카드 위에 한 겹 더 뜨는 후보 창을 띄운다([Desktop의 식별 흐름](character-search.md#desktop의-식별-흐름) 4번, 2026-10-27 [Issue #815](https://github.com/blahaj94/dfragon/issues/815)). 후보 창은 카드보다 위로 6, 오른쪽으로 8 비켜 있고 위쪽 2px 크림 선과 그림자를 쓰며, 카드를 덮어도 된다. 머리 글자 없이 오른쪽 위에 24×24 닫기 X 버튼만 두고, 본문은 후보의 얼굴 초상화(64×64)만 한 줄로 둔다. 이름은 후보끼리 같으므로 쓰지 않고, 서버와 모험단은 `title`과 보조 기술 이름(`카인, 달빛아래늑대무리`)에만 둔다. 지금 고른 후보는 회색 테두리, 미리보기 중인 후보는 크림 테두리와 오른쪽 위 체크다. 카드 폭에 다 들어가지 않으면 가로로 넘긴다. 한 번 누르면 그 후보로 미리보기하고, 미리보기 중인 초상화를 다시 누르면 확정한다. 미리보기 결과는 창 안 표시로 확인하고 카드 내용은 확정 뒤에 본다.

닫기 X로 닫으면 카드 머리 줄 오른쪽(스냅샷 칩 앞)에 `후보 4`처럼 후보 수를 단 칩이 남고, 칩을 누르면 후보 창이 다시 열린다. 칩은 열고 닫는 버튼이라 `aria-expanded`로 열림을 전한다. 확정하거나 다음 회차가 시작되면 후보 창과 칩이 함께 사라진다. 확정 뒤 다시 바꾸려면 이름 칸 안 서버 선택을 쓴다. 공대 카드는 후보 창을 두지 않는다.

### 상위, 랭커 단계

상위와 랭커 단계는 UI 셸과 합성 데이터까지가 범위다. 단계를 나누는 기준(명성, 장비 점수)과 데이터 연결은 별도 과제이며, 제품 카드는 단계 데이터를 받지 않아 단계를 보이지 않는다. 단계는 조회를 마친 카드에만 보이고 이름 수정 중, 검색 실패, 결과 0건, 대기 표시가 단계보다 앞선다.

| 단계 | 꺾쇠와 움직임 | 카드 표시 |
| ---- | ------------- | --------- |
| 상위 | `tier.top` 꺾쇠가 4초 주기로 밝아졌다 흐려진다. 옅은 금색 빛줄기가 주기마다 한 번 카드를 지나간다 | 명성과 점수, 썸네일 아래 2px 선이 `tier.top` |
| 랭커 | `tier.ranker` 꺾쇠가 주기 시작에 바깥 10px에서 조여 든다. 옅은 청록 빛줄기가 지나가고 카드에 4px 간격 스캔선을 깐다 | 면 `tier.rankerSurface`, 외곽선 1px `tier.rankerOutline`, 썸네일 `tier.rankerWell`. 명성과 점수, 썸네일 아래 2px 선이 `tier.ranker` |

빛줄기는 주기의 6%에서 30% 사이에 지나가고 나머지 시간은 멈춘다. 동작 줄이기 설정에서는 빛줄기를 그리지 않고 꺾쇠 움직임을 멈추며 색과 스캔선으로 단계를 보인다. 단계 이름은 화면 글자로 쓰지 않고 보조 기술에 `상위 단계`, `랭커 단계`로 전한다.

### 공대 화면

2026-10-19 사용자 결정으로 공대 화면을 DFragon 디자인 캔버스의 `공대 화면, 12명` 보드대로 다시 그렸고, 2026-10-27 축소 시안([Issue #808](https://github.com/blahaj94/dfragon/issues/808))으로 창 높이 300에 맞췄다. 검색 하위 메뉴의 공대는 네 명씩 세 파티, 12자리를 한 보드에 보인다. 보드는 축약 카드 네 열, 세 줄이고 한 줄이 한 파티다. 파티 번호 열은 두지 않고, 자리마다 속한 파티는 보조 기술에 설명으로 전한다. 카드 폭은 창 폭을 네 등분하고 간격은 8이다. 1280×300 창에서 12장이 스크롤 없이 들어가며, 창이 작아 넘치면 보드 영역이 스크롤한다. 자리 맞바꾸기 표시와 포커스 선이 잘리지 않도록 보드 둘레에 여백을 둔다.

공대 카드는 파티 카드와 같은 구조의 축약 카드다. 카드 안 여백은 위 8, 좌우 8, 아래 6이고, 썸네일 40 오른쪽 열에 이름 칸, 소속 줄, 명성과 점수 한 줄을 둔다. 머리 줄 오른쪽 끝에는 상태 표시(이름 수정 중 점 3개, 실패 `!`, 인식 대기 각진 모래시계), 스냅샷 순번 칩, 자리 번호(`01`~`12`)를 이 순서로 둔다. 면 탭, 스탯 한 줄, 서버 순위, 상세 열기 버튼은 없다. 상태는 파티 카드와 같은 꺾쇠(기본, 이름 수정 중, 검색 실패와 결과 0건, 빈 카드와 인식 대기의 점선)와 상위, 랭커 단계로 보이며, 상위, 랭커는 자리 번호 칩, 썸네일 아래 선, 명성과 점수를 단계 색으로 그린다. 점수는 파티 카드와 같은 카드 값에서 오고(2026-10-19, Issue #716), 점수 라벨과 색, 보조 기술 문구는 파티 카드와 같다. 찾지 못한 자리의 실패, 결과 0건, 입력 안내는 소속 줄 자리에 한 줄로 두고, 길면 말줄임하며 전체 문구는 `title`로 전한다. 찾은 자리의 선택 근거 안내는 소속 줄을 가리지 않도록 보조 기술과 `title`에만 전한다. 선택 근거 안내는 [공대 식별 흐름](character-search.md#desktop의-공대-식별-흐름)을 따라 직업명이나 수치로 확정한 선택이면 두지 않고, 수치로 확정하지 못했으면 `명성으로 추정한 후보입니다.`나 `장비 점수로 추정한 후보입니다.`, 직업과 수치를 확인하지 못한 최고 명성 선택이면 `직업과 수치 미확인, 최고 명성 후보입니다.`다. 공대 카드는 후보 창을 두지 않는다. 조회 중과 공대 캡처의 인식 중에는 썸네일 가운데에 진행 표시를 둔다. 응답에 없는 값은 파티 카드처럼 `-`로 보인다.

파티 카드처럼 이름 칸에 입력하고 서버를 고르면 그 자리만 조회하며, 빈 자리도 이름 입력과 서버 선택부터 시작한다. 실패와 결과 0건 안내는 Alt+R로 다시 인식하거나 서버와 이름을 직접 조회하도록 알린다. 12자리는 서로 독립된 조회 상태를 가진다. 공대 조회는 파티 카드의 수동 조회와 다른 검색 수명을 써서 파티 네 자리와 공대 12자리가 서로를 덮어쓰지 않는다. 한 자리를 다시 조회하면 그 자리의 이전 요청을 취소하고 늦은 결과를 반영하지 않으며 다른 자리의 요청은 유지한다. Main은 공대 조회의 자리 번호(0 이상 11 이하 정수)와 입력을 다시 검사한다. 파티와 공대 화면을 오가도 두 화면의 입력과 조회 결과는 유지된다. 공개 검색에는 클라이언트별, 서버 전체 호출 제한이 없다. 앞단 proxy가 호출 제한으로 429를 반환하면 일부 자리에 호출 제한 안내가 보일 수 있다.

카드를 끌어 다른 카드에 놓으면 두 자리를 맞바꾼다. 놓을 자리는 카드 안쪽 2px 신호색 선, 끄는 카드는 흐리게 보인다. 키보드로는 카드(접근 가능한 이름 `n번 자리, 끌어서 옮기기`)에 포커스한 채 Alt와 방향키로 위, 아래 파티나 같은 파티의 왼쪽, 오른쪽 자리와 맞바꾸며, 옮긴 카드에 포커스가 남아 이어서 옮길 수 있다. 카드 안의 이름 칸과 버튼은 방향키를 그대로 쓴다. 실제로 맞바꿨을 때만 보조 기술에 `n번 자리와 m번 자리를 맞바꿨습니다.`를 알리며 같은 두 자리를 다시 맞바꿔도 다시 알린다. 자리마다 속한 파티와 키보드 조작은 설명으로 전한다. 끄는 동안 회차가 바뀌거나 배치가 바뀌거나 맞바꿀 수 없게 되면 그 끌기는 끝나며, 다른 앱에서 끌어 온 글자나 파일은 자리 맞바꾸기로 받지 않는다. 맞바꾸기는 화면 자리에 놓인 검색 슬롯만 바꾸므로 그 자리의 입력, 검색 상태와 결과, 진행 중 조회와 늦은 응답이 카드와 함께 옮겨 가고 main 공대 검색의 자리 번호 계약은 바뀌지 않는다. 공대 캡처가 인식하는 동안(검색 수명 시작부터 이름 인식을 마치거나 회차가 끝날 때까지)은 끌기와 키보드 맞바꾸기를 받지 않고 이름에서 `끌어서 옮기기`를 뺀다. 회차는 12자리를 비우고 게임 화면의 행 순서대로 1~12번 자리를 채우므로 시작할 때 배치를 처음으로 되돌린다.

머리는 파티 머리와 같은 상단 바 안의 한 줄이다. 왼쪽에 제목 `공대`, 캐릭터를 찾은 자리 수(`10/12`처럼 Barlow Condensed 16px, 분모는 흐린 글자)와 안내를, 오른쪽에 마지막 캡처, 스냅샷 버튼, 캡처 버튼을 둔다. 스냅샷은 파티와 같은 토글이며 스냅샷을 따로 가진다([모험단 순번 스냅샷](#모험단-순번-스냅샷)). 머리의 안내는 검색 연결 실패만 보이고, `캡처 대기`나 공대 회차 진행 문구는 두지 않는다([공대 캡처](#공대-캡처)).

### 공대 캡처

2026-10-19 사용자 요청으로 공대 화면의 Alt+R 캡처를 채택했다. 공대 화면을 보는 동안 Alt+R과 공대 머리의 캡처 버튼은 공대 회차를 시작하고 파티 회차는 시작하지 않는다. 캡처 버튼은 파티 머리와 같은 높이 28의 주 버튼(카메라 아이콘과 `Alt R`)이고 접근 가능한 이름은 `공대 캡처, 단축키 Alt R`이다. 누르면 Alt+R과 같은 회차를 시작하며 대화상자를 열지 않는다. 창 등록 전, 등록 중, 등록 실패, 공대 검색 수명을 시작하는 동안, 중지 뒤처럼 Alt+R이 공대 회차를 시작하지 않는 상태에서는 누를 수 없다. 마지막 캡처는 파티와 같은 방식으로 마지막으로 인식을 마친 공대 회차의 완료 시각을 보이며, 진행 중 공대 회차가 창 변경이나 중지로 끝나면 `-`가 된다.

회차는 12자리를 비우고 게임 화면의 12행 공대 상세 창에서 공대원 이름을 읽어 화면 순서대로 1~12번 자리에 넣고, 이름을 읽은 자리마다 조회를 시작한다([Windows 캡처 정책](desktop-windows-capture.md#windows-제품-캡처-정책)). 공대 상세 창에는 서버가 없어 그 행의 직업명과 명성이나 장비 점수로 같은 이름의 후보 중 한 캐릭터를 고르며(2026-10-20 [#760](https://github.com/blahaj94/dfragon/issues/760) 결정), 서버와 이름은 카드에서 고쳐 다시 조회할 수 있다. 인식하는 동안 카드는 진행 표시를 보이고 읽은 이름을 이름 칸에 둔다. 회차가 진행되는 동안 사용자가 서버와 이름으로 조회한 자리는 그 회차의 늦은 인식 결과로 덮지 않는다. 진행 문구는 파티 캡처와 같은 단계를 쓴다(`공대를 인식하고 있습니다.`, `인식을 마쳤습니다. 다시 인식하려면 Alt+R을 누르세요.`). 공대 상세 창을 찾지 못하거나 창이 둘 이상이거나 공대원 이름을 찾지 못하면, 게임 창이 가려졌거나 읽을 수 없으면 Alt+R 전에 확인할 내용을 알리고 회차를 끝낸다. 글자 인식과 검색 시작 실패도 안내 후 Alt+R로 다시 시작할 수 있다. 공대 화면을 보는 동안 상단 바 상태 칩과 캡처 창은 창이 등록돼 있으면 공대 회차의 상태(`인식 중`, `인식 완료`, `확인 필요`, `캡처 실패`)와 문구를, 창 등록 전과 등록 실패, 중지 뒤에는 창 선택 상태를 보인다. 공대 머리도 파티 머리와 같은 기준으로 `캡처 대기`와 공대 회차 진행 문구를 두지 않고, 검색 연결 실패처럼 캡처 진행이 아닌 안내만 보인다. 공대 회차 문구는 상단 바의 화면 밖 캡처 안내 하나가 보조 기술에 알려, 공대 머리와 두 번 읽히지 않는다.

공대 화면의 창 내용 높이는 300이고, 파티 화면으로 돌아가면 163으로 돌아온다([상단 바](#상단-바)의 창 크기). 카드 접기는 두지 않는다.

### 모험단 순번 스냅샷

2026-10-20 담당자 요청([Issue #731](https://github.com/blahaj94/dfragon/issues/731))으로 파티와 공대 머리의 스냅샷 버튼을 켜는 토글로 채택했다. 사람은 모험단으로 구분하므로 같은 사람이 다른 캐릭터로 바꿔 들어와도 같은 모험단이면 같은 사람이다.

- 켜기: 버튼을 누르는 순간 지금 캐릭터를 찾은 자리의 모험단명을 자리마다 저장한다. 빈 자리, 검색 실패와 결과 0건 자리, 모험단 조회가 실패해 모험단명이 없는 자리는 저장하지 않는다.
- 자리가 바뀐 카드: 다시 캡처하거나 조회한 뒤 스냅샷 때와 자리가 다른 카드에만 머리 줄 오른쪽 끝에 `스냅샷 순번 N` 칩(파티 1~4, 공대 1~12)을 보인다. 같은 자리면 칩이 없다. 카드를 자동으로 옮기지 않는다. 공대는 화면 자리 기준이라 카드를 맞바꾸면 칩이 생긴다.
- 스냅샷에 없는 모험단: 카드 전체를 빨간 빗금과 안쪽 2px 빨간 선으로 덮고 머리 줄에 빨간 `!` 칩(`스냅샷에 없는 모험단`)을 보인다. 덮는 층은 클릭을 막지 않고 보조 기술에서 숨긴다. 빈 자리를 포함해 스냅샷의 모험단 밖의 모험단이 어느 자리에 보여도 같다.
- 같은 모험단의 캐릭터가 둘 이상: 지금 자리에 스냅샷과 같은 모험단이 있으면 그 자리를 먼저 맞추고, 남은 캐릭터에 스냅샷의 자리를 자리 순서대로 배정한다. 스냅샷보다 많이 들어온 캐릭터는 스냅샷에 없는 모험단으로 본다. 모험단명이 없는 카드는 칩과 경고를 모두 보이지 않는다. 이 둘과 검색 실패 자리를 스냅샷에서 빼는 것은 시안과 디자인 문서의 판단이며 담당자가 다르게 정하면 따른다.
- 끄기: 켜진 버튼을 누르면 버튼 아래에 `스냅샷을 지우시겠습니까?` 확인(`role="alertdialog"`, `취소`와 `지우기`)을 열고, `취소`에 먼저 포커스한다. `지우기`만 스냅샷을 지우고 칩과 경고를 걷는다. Escape와 바깥 누름은 스냅샷을 지우지 않는다.
- 접근성: 버튼은 켜짐을 `aria-pressed`로 전하고 이름 `파티 모험단 순번 스냅샷`, `공대 모험단 순번 스냅샷`은 켜고 꺼도 바뀌지 않는다. 칩은 `role="img"`와 이름으로 상태를 색만으로 전하지 않는다. 칩과 덮는 층은 전환 없이 바로 나타나고 사라지며, 토글 버튼의 색 전환은 동작 줄이기에서 0이다.
- 회차 번호: 스냅샷이 켜진 동안 파티와 공대 머리의 인원수(`2/4`, `10/12`) 바로 오른쪽 같은 줄에 `#1`, `#2`처럼 몇 번째 회차인지 보인다. Barlow Condensed 16px 700, 신호색(크림 `#F8E8C8`), `line-height` 1이며 `#`도 숫자와 같은 크기다. 스냅샷을 켠 순간이 `#1`이고, 켜 둔 동안 캡처 버튼이나 Alt+R로 회차를 시작하는 순간 하나 오른다. 인식을 마치기 전에 시작만 해도 세며 실패하거나 취소된 회차도 한 회차다. 받아들이지 않은 시작(창이 없거나 수명 시작을 기다리는 중)과 창 선택, 중지는 세지 않는다. 스냅샷을 끄면(확인 뒤) 번호가 사라지고 다시 켜면 `#1`부터다. 파티와 공대가 따로 센다. 접근 가능한 이름은 `N번째 파티`, `N번째 공대`(`role="img"`)다.
- 수명: 스냅샷과 회차 번호는 renderer 메모리에만 두고 IPC, 디스크, 저장소에 남기지 않아 앱을 끄면 사라진다. 파티와 공대는 따로 가지며 한쪽을 지워도 다른 쪽은 그대로다.

## 표현과 이미지

- Desktop은 다크 테마 하나만 쓰고 저장된 라이트 설정은 읽지 않는다(2026-10-27, [Issue #818](https://github.com/blahaj94/dfragon/issues/818)).
- 글꼴은 번들한 마루미냐 한글(MaruMinya Hangul)이며 한국어 줄바꿈과 표기 기준은 [글꼴과 한국어 타이포그래피](design-system.md#글꼴과-한국어-타이포그래피)를 따른다. 한글 글자는 12px 하나(행간 14)로 쓰고, 숫자는 상단 바의 인원수, 회차, 마지막 캡처 초만 Barlow Condensed로 쓴다.
- 무료 아이콘의 디자인 원본은 [Lucide 아이콘 목록](https://lucide.dev/icons)이다. 현재 사용 중인 camera, chevron-down, check, monitor, refresh-cw, external-link를 기준으로 구현 자산과 출처를 맞추고, 선 끝과 꺾임은 각지게(`stroke-linecap="square"`, `stroke-linejoin="miter"`) 그린다. 대기(각진 모래시계), 스냅샷은 dfragon-design [아이콘](https://github.com/blahaj94/dfragon-design/blob/main/design/icons.md)의 DFragon 아이콘을 쓴다.
- 캐릭터 이미지: `https://img-api.neople.co.kr/df/servers/<serverId>/characters/<characterId>?zoom=<zoom>`.

이미지 로딩은 HTTPS `https://img-api.neople.co.kr` 고정 origin 하나만 허용한다. Renderer CSP의 `img-src`는 이 origin과 `self`, `data:`만 둔다. `*`, 임의 origin, renderer fetch, Neople API key를 추가하지 않는다. URL은 검증한 식별자와 고정 base로 구성하고 외부 데이터의 임의 URL을 그대로 사용하지 않는다. 네트워크 오류, 누락, 이미지 decode 실패에는 같은 크기의 대체 표시를 둔다. 합성 미리보기는 출처를 기록한 로컬 자산을 사용하며 제품 CSP의 원격 허용을 선행하지 않는다.

## 장비 점수 표시

장비 점수는 Desktop main의 점수 엔진이 계산해 카드 값에 담고(Issue #716 3번 항목), renderer는 계산식을 추정하지 않는다. 엔진이 없거나 계산하지 못하면 `-`이고, 계산을 건너뛴 결과에 엔진이 근사값을 냈으면 위 캐릭터 면 설명대로 `≈`를 붙여 보인다. 근사값은 카드 표시에만 쓰고 공대 식별의 장비 점수 비교에는 쓰지 않는다. 정확한 점수의 예측값 표시는 위 캐릭터 면 설명대로 보조 기술과 마우스 설명에만 둔다. 근사값의 `≈`는 Issue #784에서 정한 화면 표시이며, 디자인 결정 기록(blahaj94/dfragon-design#40)에는 아직 반영되지 않았다.

## 구현 완료 확인

- 1280 × 163 파티 화면과 1280 × 300 공대 화면, 최소 폭 1024와 그 사이 폭에서 파티 카드와 입력, 상단 바의 머리와 캡처 버튼, 캡처 창이 잘리지 않고, 공대 카드 12장은 1280 × 300에서 스크롤 없이 보인다. 공대 카드는 끌기와 Alt 방향키로 자리를 맞바꾼다. 글꼴과 이미지 실패도 레이아웃을 무너뜨리지 않는다.
- 한 슬롯을 조작해도 다른 슬롯은 유지된다. 키보드 포커스가 보이고 중첩 버튼이 없다.
- 캡처 여부와 무관하게 이름과 서버를 수정할 수 있다. 카드 중앙의 진행 표시, 0건, 최고 명성 대체 표시, 429와 네트워크 실패를 구분한다.
- 이름, 서버 변경 또는 capture 종료 후 늦은 응답이 이전 캐릭터를 복원하지 않는다.

검증 명령은 [scripts 안내](../../scripts/README.md#native-validation)를 따른다. Desktop 변경 시 `pnpm --filter @dfragon/desktop test`, `lint`, `build`를 영향 범위에 맞게 실행한다. `build`는 typecheck를 포함한다. 합성 fixture의 시각 확인과 Windows 제품의 캡처, 검색 성공을 구분해 PR에 기록한다. 이 이관 문서만 변경할 때는 문서 연결, 내용, diff를 확인하고 앱 빌드를 반복하지 않는다.
