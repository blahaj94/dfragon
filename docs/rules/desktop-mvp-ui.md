# Desktop MVP 카드 UI

확정 Penpot 디자인의 메인 카드, 상세 A안과 접근성 요구사항을 정의한다. 기본 앱 진입점은 슬롯 네 개, 테마 전환, 로그인 전용 창과 캡처 모달을 사용한다. OCR 식별 IPC의 슬롯 상태와 선택된 캐릭터의 기본 정보를 카드에 연결한다. [Issue #595](https://github.com/blahaj94/dfragon/issues/595)의 자동 캡처, 첫 후보 검색, 최고 명성 대체 표시와 상시 수동 입력은 구현 PR의 사용자 merge 후 적용한다. 합성 데이터의 상태와 카드 전환 미리보기는 별도 진입점에 유지하며 Windows 실사용 검증과 구분한다.

디자인 원본, 현재 연결 지점, 실행 명령은 [디자인 이관 안내](../reference/desktop-mvp-design-handoff.md)를 참고한다.

## 캡처 모달

카메라 버튼으로 화면 캡처 모달을 연다. 앱을 시작할 때 창 목록을 조회하고, 던파 후보가 없거나 조회가 실패하면 완료 시점부터 15초 뒤 다시 조회한다. 던파 후보를 찾으면 반복 조회를 멈춘다. 수동 새로고침과 화면 종료는 이전 타이머를 해제하며 늦은 응답을 반영하지 않는다. 진행 중인 자동 조회와 다음 자동 조회를 겹치지 않게 하고, 자동 재조회 실패로 기존 캡처 상태 문구를 덮어쓰지 않는다.

창 목록은 감지된 던파 창을 먼저 표시하고 다른 창도 직접 선택할 수 있다. 앱 시작 시 또는 이후 조회에서 던파 창이 하나만 확인되면 main의 선택 등록 후 자동 캡처한다. 여러 후보 중 하나를 임의로 선택하지 않는다. 사용자가 직접 중지하거나 다른 창을 선택한 뒤 자동 감지가 그 의도를 덮어쓰지 않는다. 연속 선택, 중지, unmount 뒤 늦은 선택 완료로 캡처를 시작하지 않는다. 캡처 중 다른 창을 고르면 이전 worker와 검색 수명을 정리하고 전환하며 별도 시작 버튼을 두지 않는다.

일반 캡처는 실제 게임 client 영역에서 개발자 이미지 수집과 같은 HP, MP 검출기로 닉네임을 찾는다. 해상도와 UI 배율은 현재 프레임에서 검출하며 가득 찬 HP, MP와 주변 경계를 대상으로 한다. 잔량이 줄어든 전투 화면은 지원 범위 밖이다. 검색이 끝난 슬롯은 파티원 교체, 가림이나 미검출로 재검색하거나 비우지 않는다. Alt+R은 새 캡처, OCR, 전체 파티 조회를 처음부터 실행한다. 수동 입력은 선택한 슬롯만 새로 조회한다.

모달의 닫기, Escape와 로그인 상태 변경은 캡처를 유지한다. 캡처 중지는 별도 버튼으로 처리한다. 준비, 캡처 중에는 카메라 아이콘을 주황색으로 표시하며 실패, 빈 목록은 새로고침, 재선택할 수 있게 한다. 각 카드 중앙의 Process Circle은 OCR부터 캐릭터 확인까지 표시한다. 빈 슬롯에 별도 비활성 상태는 추가하지 않는다.

2026-09-18 요청의 범위는 Windows 제품 캡처와 Mac에서 볼 수 있는 합성 UI 미리보기다. 제품 renderer에 OS 분기를 추가하지 않으며 기존 main 권한 정책은 유지한다. 이 연결 범위는 해당 PR에서 구현, 검증하고 사용자 merge로 활성화한다.

## 메인 화면과 슬롯

디자인 기준은 바깥 좌우 24px, 위 16px, 헤더 아래 16px, 본문 안쪽 16px, 카드 간격 12px다. 카드 높이는 280px이며 폭은 반응형으로 변한다.

| 화면 폭 | 한 줄 카드 수 | 카드 폭  |
| ------- | ------------- | -------- |
| 900px   | 4             | 196px    |
| 700px   | 3             | 약 199px |
| 500px   | 2             | 204px    |
| 300px   | 1             | 220px    |

위 값은 확인할 디자인 표본이며 각 숫자를 breakpoint로 그대로 사용한다는 뜻은 아니다. 중간 폭에서도 줄바꿈, 간격, 가독성이 이어지도록 구현한다. 새로고침이나 다른 슬롯의 조작 때문에 한 슬롯의 카드 면이 바뀌지 않도록 상태를 분리한다.

기본 면에는 중앙 캐릭터 이미지 아래 모험단명, 이름 입력, 직업, 명성을 배치한다. 장비, 서약 면에는 이름, 서버를 반복하지 않는다. 장비 아이콘 위 강화, 증폭 숫자, 마법부여 마름모, 크리티컬, 스위칭 표시는 최종안에서 제거됐다. 강화 수치와 마법부여 등급은 투자 현황 면의 12부위 목록에서 확인한다.

| 상태                                | 카드 본문                                    | 이름 입력           | 상세 열기                                  |
| ----------------------------------- | -------------------------------------------- | ------------------- | ------------------------------------------ |
| 조회 완료, 캐릭터 선택됨             | 한 번 누를 때마다 다음 면, 네 번째에 기본 면 | 수정 가능           | 우측 상단 아이콘으로 별도 실행             |
| 이름 수정 중                        | 입력과 면 전환을 분리                        | 수정, 검색 확정 가능 | 다른 캐릭터의 이전 상세를 열지 않도록 처리 |
| 검색 실패                           | 빨간 테두리와 실패 안내, 면 전환 없음        | 수정 가능           | 아이콘을 비활성 상태로 표시                |
| 활성 capture 안의 인식 대기, 빈 카드 | 호버 반응과 면 전환 없음                     | 직접 입력 가능      | 아이콘 없음                                |

입력, 서버 선택, 상세 버튼 조작은 카드 면을 넘기지 않는다. 카드 전체를 하나의 `button`으로 만들고 내부에 input/button을 중첩하지 않는다. 컨테이너 안에 면 전환 버튼과 입력, 상세 버튼을 형제 요소로 배치하고, 키보드로도 각각 접근할 수 있게 한다. 상세 아이콘은 호버뿐 아니라 키보드 포커스로도 드러나며, 호버가 없는 환경에서도 사용할 수 있어야 한다.

이름과 서버는 캡처 여부와 관계없이 항상 수정할 수 있다. Enter 또는 서버 변경으로 지정한 서버와 닉네임을 조회한다. 수동 검색은 캡처와 독립된 검색 수명에서 실행하며 이전 OCR 응답이 수동 선택을 덮어쓰지 않는다. 수동 조회 자체는 OCR이나 자료 업로드를 실행하지 않는다.

디자인의 빈 카드는 API의 검색 결과 0건과 같은 뜻이 아니다. 기존 `SearchSlot.state`의 `idle`, `pending`, `success`, `empty`, `failure`를 유지하고 0건, 통신 오류와 호출 제한을 구분한다. 서버 선택은 지원하는 전체 서버를 제공한다. OCR의 첫 번째 후보에 이름이 없거나 그 이름의 검색 결과가 없으면 조회 실패를 표시하며 두 번째 후보로 넘어가지 않는다.

이름의 검색 결과가 있으면 명성 내림차순으로 외형을 확인한다. 명성 null은 마지막이며 처음 비교 기준을 통과한 캐릭터를 선택한다. 외형을 확인할 수 없거나 모두 불일치하면 가장 명성이 높은 후보를 표시하고 외형으로 확정한 결과와 구분해 안내한다. 명성 0과 null을 구분하고 알 수 없는 값은 `—`로 표시한다. 후보 조회와 상세 조회 자체의 통신 오류를 조회 성공으로 바꾸지 않는다.

현재 제품 연결은 기본 정보 면으로 제한한다. 아직 연결하지 않은 장비, 서약과 평가 데이터를 만들어 넣거나 카드 면 전환을 활성화하지 않는다. 기존 합성 미리보기의 네 면 비교는 유지한다. 실패는 정제된 오류를 표시하며 Alt+R 또는 수동 입력으로 새 조회를 시작한다. 이미지 CSP와 고정 네오플 origin 정책은 유지한다.

## 상세창 A안

1120×680 기준으로 상단 캐릭터 정보, 장비 점수, 명성을 유지하고, 그 아래 선택된 736×480 카드를 전면에 둔다. 뒤의 카드들은 회전 없이 오른쪽으로 84px, 아래로 8px씩 겹쳐 다른 정보의 존재와 이름이 보인다. 보이는 카드를 누르면 해당 카드가 앞으로 나온다. 현재 프로토타입은 180ms dissolve이며 실제 이동의 느낌은 renderer에서 확인한다. 모션 감소 설정에서는 불필요한 이동을 줄인다.

| 카드     | 내용                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 장비     | 중앙 캐릭터와 양쪽 장비 슬롯                                                 |
| 서약     | 같은 구도의 서약 슬롯. 상세창의 칭호, 오라, 크리쳐는 장비 카드와 동일하게 유지 |
| 강화     | 12부위의 강화, 증폭 수치. 아이콘 위에 숫자를 겹치지 않음                      |
| 마법부여 | 12부위의 종결, 준종결, 기타 텍스트. 현재 등급은 디자인 예시                    |
| 스킬트리 | 구성 예정 상태만 존재. 실제 스킬트리 UI는 후속 범위                          |

기존의 “서약으로 전환” 버튼은 없다. 강화와 마법부여는 상세창에서는 별도 카드이며, 메인 08의 작은 투자 현황 면과 구분한다. 12부위 목록에는 칭호, 오라, 크리쳐를 넣지 않는다. 08의 작은 서약 면과 07 상세창의 슬롯 구성을 무조건 동일하게 만들지 않는다.

## 표현과 이미지

- 라이트 메인 보드도 캐릭터 카드 면은 다크 색상을 유지하며 바깥 배경, 헤더, 본문 패널, 하단 바를 밝게 바꾼다.
- 글꼴은 번들한 Pretendard이며 한국어 줄바꿈과 표기 기준은 [글꼴과 한국어 타이포그래피](design-system.md#글꼴과-한국어-타이포그래피)를 따른다. 2026-09-19 Typo 적용 요청에 따라 작은 투자 현황 목록은 `Typo.caption`(12px/18px), 상세 목록은 `Typo.txtS`(14px/20px) 일반 두께로 맞춘다. 상세 행은 위아래 4px padding으로 기존 행 높이를 유지한다. 테이블의 교차 행 배경은 `#22262C` / `#2B3037`이다.
- 무료 아이콘의 디자인 원본은 [Lucide 아이콘 목록](https://lucide.dev/icons)이다. 현재 사용 중인 sun, moon, camera, x, chevron-down, user, external-link를 기준으로 구현 자산과 출처를 맞춘다.
- 캐릭터 이미지: `https://img-api.neople.co.kr/df/servers/<serverId>/characters/<characterId>?zoom=<zoom>`.
- 아이템 이미지: `https://img-api.neople.co.kr/df/items/<itemId>`.
- 서약 대표 이미지는 임시 [발키리 이미지](https://bbscdn.df.nexon.com/data7/showroom/static/icon/oath_09_valkyrie/00001.png)를 사용한 상태다. 이 그림으로 실제 서약 종류를 판정하지 않는다. 종류별 자산 매핑은 후속이다.

| 장비 희귀도 | 테두리 색상 | 장비 희귀도 | 테두리 색상 |
| ----------- | ----------- | ----------- | ----------- |
| 커먼        | `#FFFFFF`   | 언커먼      | `#68D5ED`   |
| 레어        | `#B36BFF`   | 유니크      | `#FF00FF`   |
| 에픽        | `#FFB400`   | 레전더리    | `#FF7800`   |
| 크로니클    | `#FF6666`   | 태초        | `#50E3C2`   |

마법부여 표시색은 종결 `#50E3C2`, 준종결 `#FFB400`, 기타 `#FFFFFF`다. 등급 텍스트를 함께 표시하며 색만으로 판정 결과를 전달하지 않는다. **판정 기준이 없는 실제 데이터를 `기타`로 간주하거나 디자인의 예시 등급을 실사용 캐릭터에 복사하지 않는다.**

이미지 로딩은 HTTPS `https://img-api.neople.co.kr`와 `https://bbscdn.df.nexon.com` 두 고정 origin만 허용한다. 실데이터 연결 구현에서 renderer CSP의 `img-src`에 이 origin만 추가하고 기존 `self`, `data:`를 유지한다. `*`, 임의 origin, renderer fetch, Neople API key를 추가하지 않는다. URL은 검증한 식별자와 고정 base로 구성하고 외부 데이터의 임의 URL을 그대로 사용하지 않는다. 네트워크 오류, 누락, 이미지 decode 실패에는 같은 크기의 대체 표시를 둔다. 합성 미리보기는 출처를 기록한 로컬 자산을 사용하며 제품 CSP의 원격 허용을 선행하지 않는다.

## 후속 연결에서 남은 결정

장비, 서약, 강화 표시는 우선 구현할 수 있다. 마법부여 자동 평가와 실제 스킬트리, 서약 종류별 대표 이미지 매핑은 후속 범위다. 아래 결정은 관련 동작을 구현할 때 확인하며 독립적인 화면 작업을 막지 않는다.

- **마법부여 미평가 상태:** 판정 기준을 정하기 전 카드에 안내를 표시할지, 해당 카드를 숨길지 결정이 필요하다. `기타`는 미평가 상태의 대체 값이 아니다.
- **상세 장비 연결:** 기본 정보 상세 창은 캐릭터별로 열고 같은 캐릭터는 재사용한다. 메인 창을 실제로 닫으면 상세 창을 함께 닫으며 장비 확장은 후속 범위다.
- **장비 점수:** 시안에는 값이 있지만 검색 응답에는 없다. 상세 응답의 실제 대응 필드, 누락 표시를 확인하며 계산식을 추정하지 않는다.

## 구현 완료 확인

- 900, 700, 500, 300px와 중간 폭, 다크, 라이트에서 카드와 입력, 상세 버튼이 잘리지 않는다. 글꼴과 이미지 실패도 레이아웃을 무너뜨리지 않는다.
- 한 슬롯을 넘겨도 다른 슬롯은 유지된다. 이름, 서버, 상세 버튼 조작은 면 전환을 일으키지 않는다. 키보드 포커스가 보이고 중첩 버튼이 없다.
- 캡처 여부와 무관하게 이름과 서버를 수정할 수 있다. 카드 중앙의 진행 표시, 0건, 최고 명성 대체 표시, 429와 네트워크 실패를 구분한다.
- 이름, 서버 변경 또는 capture 종료 후 늦은 응답이 이전 캐릭터를 복원하지 않는다. 장비와 서약의 부위, 색상, 칭호, 오라, 크리쳐가 각 원본 보드와 일치한다.
- 상세 A안의 카드 선택, 모션 감소, 창 열기, 닫기와 재열기를 실제 Electron에서 확인한다. 실데이터에 예시 마법부여 등급을 표시하지 않는다.

검증 명령은 [scripts 안내](../../scripts/README.md#native-validation)를 따른다. Desktop 변경 시 `pnpm --filter @dfragon/desktop test`, `lint`, `build`를 영향 범위에 맞게 실행한다. `build`는 typecheck를 포함한다. 합성 fixture의 시각 확인과 Windows 제품의 캡처, 검색, 별도 창 성공을 구분해 PR에 기록한다. 이 이관 문서만 변경할 때는 문서 연결, 내용, diff를 확인하고 앱 빌드를 반복하지 않는다.
