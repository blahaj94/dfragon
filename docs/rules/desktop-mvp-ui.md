# Desktop MVP 카드 UI

확정 Penpot 디자인의 메인 카드, 상세 A안과 접근성 요구사항을 정의한다. 기본 앱 진입점은 상단 바, 슬롯 네 개, 테마 전환, 시스템 기본 브라우저로 여는 로그인과 캡처 모달을 사용한다. OCR 식별 IPC의 슬롯 상태와 선택된 캐릭터의 기본 정보를 카드에 연결한다. [Issue #595](https://github.com/blahaj94/dfragon/issues/595)의 창 자동 감지, 첫 후보 검색, 최고 명성 대체 표시와 상시 수동 입력은 구현 PR의 사용자 merge 후 적용한다. 합성 데이터의 상태와 카드 전환 미리보기는 별도 진입점에 유지하며 Windows 실사용 검증과 구분한다.

디자인 원본, 현재 연결 지점, 실행 명령은 [디자인 이관 안내](../reference/desktop-mvp-design-handoff.md)를 참고한다.

## 상단 바

메인 창 맨 위에 폭 전체, 높이 56px의 상단 바를 둔다. 왼쪽부터 로고(마크와 제품 이름), 내비, 게임 연결 상태 칩, 카메라, 테마, 로그인, 설정 버튼 순서다. 내비는 검색, 캐릭터, 도구, 플래너다. 현재 화면인 검색은 파티와 공대를 고르는 하위 메뉴를 열고 현재 하위 이름을 함께 보인다. 공대를 고르면 파티 카드는 상태를 유지한 채 숨기고 공대 화면 자리로 바꾼다. 화면이 없는 캐릭터, 도구, 플래너는 누를 수 없음을 알리고 해당 화면을 구현할 때 이 Rule의 변경으로 연결한다. 게임 연결 상태 칩은 캡처 모달과 같은 상태 이름과 tone을 쓰며 모달을 열지 않아도 보인다. 카메라 버튼은 캡처 모달을 열며 회차 단축키를 `Alt`, `R` 키캡으로 함께 보인다. 키캡은 표시일 뿐 카메라 버튼이 회차를 시작하지 않는다. 창이 좁아 버튼이 겹칠 만큼 공간이 모자라면 제품 이름, 상태 칩 순서로 숨긴다. 일반 화면과 개발자 작업 공간이 같은 상단 바를 쓰며, 작업 공간을 여는 동안은 캡처를 멈추므로 내비, 상태 칩과 카메라를 숨긴다.

메인 창은 1280×800으로 열고 최소 크기는 1024×640이다. 최소 폭에서도 제품 이름만 숨기면 Windows의 OS 창 버튼과 로그인 버튼까지 있는 도구 버튼이 겹치지 않고 카드 네 장이 한 줄에 들어간다. 푸터는 두지 않으며 캡처 진행 문구는 파티 머리에서 알린다.

메인 창은 OS 제목 표시줄을 숨기고 OS 기본 창 버튼(최소화, 최대화, 닫기)을 상단 바 안에 그린다. Windows는 오른쪽 끝, macOS는 왼쪽 끝에 OS 버튼이 오며 상단 바 내용은 그 자리를 비운다. 본문을 스크롤해도 상단 바는 창 맨 위에 남고, 대화상자는 OS 창 버튼 띠 아래에 놓는다. 상단 바의 빈 영역을 끌면 창을 옮기고, 버튼과 입력은 끌기 영역에서 뺀다. Windows, Linux에서는 창 버튼의 배경과 기호 색이 현재 테마의 상단 바 색을 따르고, macOS는 OS 기본 색을 쓴다.

## 캡처 모달

카메라 버튼으로 화면 캡처 모달을 연다. 앱을 시작할 때 창 목록을 조회하고, 던파 후보가 없거나 조회가 실패하면 완료 시점부터 15초 뒤 다시 조회한다. 던파 후보를 찾으면 반복 조회를 멈춘다. 수동 새로고침과 화면 종료는 이전 타이머를 해제하며 늦은 응답을 반영하지 않는다. 진행 중인 자동 조회와 다음 자동 조회를 겹치지 않게 하고, 자동 재조회 실패로 기존 캡처 상태 문구를 덮어쓰지 않는다.

창 목록은 감지된 던파 창을 먼저 표시하고 다른 창도 직접 선택할 수 있다. 앱 시작 시 또는 이후 조회에서 던파 창이 하나만 확인되면 main에 자동으로 등록한다. 직접 선택과 자동 감지는 창 등록만 하며 인식을 시작하지 않는다. 여러 후보 중 하나를 임의로 선택하지 않는다. 사용자가 직접 중지하거나 다른 창을 선택한 뒤 자동 감지가 그 의도를 덮어쓰지 않는다. 연속 선택, 중지, unmount 뒤 늦은 선택 완료를 반영하지 않는다. 다른 창을 고르면 이전 회차와 worker, 검색 수명을 정리하고 새 창만 등록하며 별도 시작 버튼을 두지 않는다.

일반 캡처는 Alt+R마다 한 회차를 시작한다. 이전 검색, 인식 상태를 비우고 검색 수명을 시작한 뒤 게임 client 영역의 프레임을 한 장만 읽어 네 슬롯의 닉네임, 얼굴 크롭, OCR, 얼굴 비교 검색과 테스트 수집에 사용한다. 개발자 이미지 수집과 같은 HP, MP 검출기로 닉네임을 찾으며 해상도와 UI 배율은 그 회차 프레임에서 검출한다. 가득 찬 HP, MP와 주변 경계가 대상이며 잔량이 줄어든 전투 화면은 지원 범위 밖이다. 회차 프레임을 쓸 수 없거나 파티 프레임이 미검출이면 안내 후 사용자의 다음 Alt+R을 기다린다. 화면이 돌아와도 자동으로 다시 읽거나 인식을 이어가지 않는다. 일부 슬롯만 미검출이면 그 슬롯은 비워 두고 나머지만 같은 프레임으로 처리한다.

회차 진행 중이나 완료 뒤의 Alt+R은 이전 회차를 정리하고 처음부터 다시 실행하며 늦은 이전 결과를 반영하지 않는다. 검색 수명을 시작하는 동안 누른 Alt+R은 무시한다. 처리 뒤에는 다음 Alt+R, 창 변경, 중지 전까지 일반 인식용 프레임을 읽지 않는다. 검색 결과, 재시도와 상세 열기는 보관한 회차의 입력과 결과를 사용하며 수동 입력은 선택한 슬롯만 새로 조회한다. 3초 간격 반복 인식과 인식 간격 설정은 제공하지 않는다. 중지 뒤에는 창을 다시 고른 다음 Alt+R로 시작한다.

모달의 닫기, Escape와 로그인 상태 변경은 캡처를 유지한다. 캡처 중지는 별도 버튼으로 처리한다. 상단 바와 모달의 상태 칩은 회차 진행 중 `인식 중`, 완료 뒤 `인식 완료`를 표시한다. 회차 프레임을 쓸 수 없거나 파티 프레임이 없어 안내 후 끝난 회차는 `확인 필요`를 대기 톤(주의 색 없이 중립색과 각진 모래시계)으로 표시한다. 창 등록 중 `준비 중`과 창 감지 관련 표시는 유지하며, 창 미감지도 대기 톤이다. 카메라 아이콘은 회차 진행 중과 완료 뒤에 `signal`로 표시하고, 준비 중을 포함한 그 밖의 상태에서는 `fg.default`로 표시한다. 실패, 빈 목록은 새로고침, 재선택할 수 있게 한다. 각 카드 중앙의 Process Circle은 OCR부터 캐릭터 확인까지 표시한다. 빈 슬롯에 별도 비활성 상태는 추가하지 않는다.

2026-09-18 요청의 범위는 Windows 제품 캡처와 Mac에서 볼 수 있는 합성 UI 미리보기다. 제품 renderer에 OS 분기를 추가하지 않으며 기존 main 권한 정책은 유지한다. 이 연결 범위는 해당 PR에서 구현, 검증하고 사용자 merge로 활성화한다.

## 메인 화면과 슬롯

디자인 기준은 상단 바 아래 콘텐츠 영역의 네 변 여백 24px, 높이 48px의 파티 머리와 그 아래 간격 16px, 카드 간격 16px다. 카드 네 장은 언제나 한 줄에 놓이고 폭은 창 폭을 따라 변한다. 펼친 카드는 파티 머리 아래 남은 높이를 채운다(1280×800에서 632px, 1024×640에서 472px). 카드 안은 위에서부터 머리(카드 번호, 서버 선택, 서버 순위, 상태 표시, 상세 열기), 그림 칸, 모험단과 길드, 이름, 직업, 명성과 장비 점수, 면 탭이다. 그림 칸은 280px이고 창이 낮으면 그림 칸이 먼저 줄어든다.

| 창 크기              | 한 줄 카드 수 | 카드 폭 |
| -------------------- | ------------- | ------- |
| 1280 × 800           | 4             | 296px   |
| 1024 × 640(최소)     | 4             | 232px   |
| 1280 × 400(접은 창)  | 4             | 296px   |

최소 폭의 좁은 카드에서는 서버 선택의 글자를 지키려고 서버 순위를 숨긴다. 위 값은 확인할 디자인 표본이며 각 숫자를 breakpoint로 그대로 사용한다는 뜻은 아니다. 중간 폭에서도 줄바꿈, 간격, 가독성이 이어지도록 구현한다. 새로고침이나 다른 슬롯의 조작 때문에 한 슬롯의 카드 면이 바뀌지 않도록 상태를 분리한다.

파티 머리에는 제목, 캡처 진행 문구, 접기 버튼, 스냅샷 버튼을 둔다. 접기 버튼은 네 카드를 함께 접고 펼친다. 접힌 카드는 그림 칸, 직업, 면 탭이 사라지고 머리, 모험단과 길드, 이름, 명성, 장비 점수만 남는다. 사라지는 부분의 높이는 180ms에 줄고 불투명도는 120ms 직선으로 줄어든다. 그림 칸 안의 진행 표시, 안내 문구, 다시 시도 버튼도 접힌 동안 숨으며 펼치면 다시 보인다. 접힌 동안은 캐릭터 면을 보이고 펼치면 고른 면으로 돌아온다. 접을 때는 카드의 상태 전환(180ms)이 끝난 뒤 창 내용 높이를 400px로 줄이고, 펼칠 때는 카드가 펼쳐질 자리를 먼저 만들도록 창을 바로 800px로 늘린다. 동작 줄이기 설정에서는 기다리지 않는다. 연달아 누르면 마지막 상태만 창에 반영한다. 접은 높이는 최소 높이의 예외라 접은 동안 최소 높이를 400px로 낮추고 펼치면 640px로 되돌린다. 최대화, 전체 화면에서는 창 크기를 바꾸지 않으며, 창 높이는 창이 놓인 화면의 작업 영역을 넘지 않는다. 창 높이 요청은 main이 발신 화면과 값(400 이상 800 이하 정수)을 다시 검사한다. 스냅샷 버튼은 기능을 연결하기 전까지 누를 수 없다.

기본 면에는 그림 칸의 캐릭터 이미지 아래 모험단명과 길드, 이름 입력, 직업을 배치하고, 명성과 장비 점수는 모든 면의 면 탭 위에 라벨 왼쪽, 값 오른쪽으로 둔다. 서버 순위와 길드는 검색 응답에 없어 값이 있을 때만 표시한다. 장비, 서약 면에는 이름, 서버를 반복하지 않는다. 장비 아이콘 위 강화, 증폭 숫자, 마법부여 마름모, 크리티컬, 스위칭 표시는 최종안에서 제거됐다. 강화 수치와 마법부여 등급은 투자 현황 면의 12부위 목록에서 확인한다.

| 상태                                | 카드 표시                                                         | 카드 본문                         | 이름 입력           | 상세 열기                                  |
| ----------------------------------- | ----------------------------------------------------------------- | --------------------------------- | ------------------- | ------------------------------------------ |
| 조회 완료, 캐릭터 선택됨             | 회색 꺾쇠                                                         | 면 탭으로 면을 고름               | 수정 가능           | 우측 상단 아이콘으로 별도 실행             |
| 이름 수정 중                        | 신호색 꺾쇠와 카드 번호, 우측 상단 네모 점 3개                    | 입력과 면 전환을 분리             | 수정, 검색 확정 가능 | 다른 캐릭터의 이전 상세를 열지 않도록 처리 |
| 검색 실패, 결과 0건                 | 빨간 꺾쇠, 그림 칸의 사선, 우측 상단 `!` 칸                       | 실패 안내, 면 전환 없음           | 수정 가능           | 아이콘을 비활성 상태로 표시                |
| 활성 capture 안의 인식 대기, 빈 카드 | 꺾쇠 없는 점선 카드. 인식 대기는 우측 상단에 각진 모래시계        | 호버 반응과 면 전환 없음          | 직접 입력 가능      | 아이콘 없음                                |

카드 상태는 테두리 대신 네 모서리 꺾쇠의 색으로 보이며 상태 이름을 글자로 다시 쓰지 않는다. 결과 0건은 실패와 같은 모양에 `검색 결과가 없습니다` 문구를 두어 통신 오류, 호출 제한의 안내와 구분한다. 보조 기술에는 우측 상단 표시의 접근 가능한 이름과 카드의 알림 영역으로 상태를 전한다. 이름 입력에 들어가거나 고치는 동안이 이름 수정 중이며, 조회를 확정하면 해당 검색 상태로 돌아간다.

면은 카드 아래의 면 탭(캐릭터, 장비, 서약, 투자 현황)으로 고른다. 입력, 서버 선택, 상세 버튼 조작은 카드 면을 넘기지 않는다. 카드 안에 버튼이나 입력을 중첩하지 않고 면 탭, 이름 입력, 서버 선택, 상세 버튼을 형제 요소로 두어 키보드로도 각각 접근할 수 있게 한다. 면 탭은 화살표로 포커스를 옮기고 Enter, Space나 누름으로 고른다. 상세 아이콘은 호버뿐 아니라 키보드 포커스로도 드러나며, 호버가 없는 환경에서도 사용할 수 있어야 한다.

이름과 서버는 캡처 여부와 관계없이 항상 수정할 수 있다. Enter 또는 서버 변경으로 지정한 서버와 닉네임을 조회한다. 수동 검색은 캡처와 독립된 검색 수명에서 실행하며 이전 OCR 응답이 수동 선택을 덮어쓰지 않는다. 수동 조회 자체는 OCR이나 자료 업로드를 실행하지 않는다.

디자인의 빈 카드는 API의 검색 결과 0건과 같은 뜻이 아니다. 기존 `SearchSlot.state`의 `idle`, `pending`, `success`, `empty`, `failure`를 유지하고 0건, 통신 오류와 호출 제한을 구분한다. 서버 선택은 지원하는 전체 서버를 제공한다. OCR은 두 번 연속 같은 입력을 기다리지 않고 회차 프레임 한 장의 첫 후보로 확정한다. 첫 후보는 앞뒤 공백만 제거하며 두 번째 후보로 보정하지 않는다. 쓸 수 없는 첫 후보는 조회 실패로 표시하고 이유와 모델 원문은 renderer DevTools Console에만 표시한다. 첫 후보의 검색 결과가 없어도 조회 실패를 표시하며 두 번째 후보로 넘어가지 않는다.

이름의 검색 결과가 있으면 명성 내림차순으로 외형을 확인한다. 명성 null은 마지막이며 처음 비교 기준을 통과한 캐릭터를 선택한다. 외형을 확인할 수 없거나 모두 불일치하면 가장 명성이 높은 후보를 표시하고 외형으로 확정한 결과와 구분해 안내한다. 명성 0과 null을 구분하고 알 수 없는 값은 `—`로 표시한다. 후보 조회와 상세 조회 자체의 통신 오류를 조회 성공으로 바꾸지 않는다.

현재 제품 연결은 기본 정보 면으로 제한한다. 아직 연결하지 않은 장비, 서약과 평가 데이터를 만들어 넣거나 카드 면 전환을 활성화하지 않으며, 면 탭의 다른 면은 누를 수 없게 둔다. 기존 합성 미리보기의 네 면 비교는 유지한다. 실패는 정제된 오류를 표시하며 Alt+R 또는 수동 입력으로 새 조회를 시작한다. 이미지 CSP와 고정 네오플 origin 정책은 유지한다.

## 상세창 A안

1120×680 기준으로 상단 캐릭터 정보, 장비 점수, 명성을 유지하고, 그 아래 선택된 736×480 카드를 전면에 둔다. 뒤의 카드들은 회전 없이 오른쪽으로 84px, 아래로 8px씩 겹쳐 다른 정보의 존재와 이름이 보인다. 보이는 카드를 누르면 해당 카드가 앞으로 나온다. 현재 프로토타입은 180ms dissolve이며 실제 이동의 느낌은 renderer에서 확인한다. 모션 감소 설정에서는 불필요한 이동을 줄인다.

| 카드     | 내용                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 장비     | 중앙 캐릭터와 양쪽 장비 슬롯                                                 |
| 서약     | 같은 구도의 서약 슬롯. 상세창의 칭호, 오라, 크리쳐는 장비 카드와 동일하게 유지 |
| 강화     | 12부위의 강화, 증폭 수치. 아이콘 위에 숫자를 겹치지 않음                      |
| 마법부여 | 12부위의 종결, 준종결, 기타 텍스트. 현재 등급은 디자인 예시                    |
| 스킬트리 | 구성 예정 상태만 존재. 실제 스킬트리 UI는 후속 범위                          |

기존의 “서약으로 전환” 버튼은 없다. 강화와 마법부여는 상세창에서는 별도 카드이며, 메인 08의 작은 투자 현황 면과 구분한다. 12부위 목록에는 칭호, 오라, 크리쳐를 넣지 않는다. 08의 작은 서약 면과 07 상세창의 슬롯 구성을 무조건 동일하게 만들지 않는다.

## 표현과 이미지

- 라이트 메인 보드도 캐릭터 카드 면은 다크 색상을 유지하며 바깥 배경과 상단 바를 밝게 바꾼다.
- 글꼴은 번들한 Pretendard이며 한국어 줄바꿈과 표기 기준은 [글꼴과 한국어 타이포그래피](design-system.md#글꼴과-한국어-타이포그래피)를 따른다. 2026-09-19 Typo 적용 요청에 따라 작은 투자 현황 목록은 `Typo.caption`(12px/18px), 상세 목록은 `Typo.txtS`(14px/20px) 일반 두께로 맞춘다. 상세 행은 위아래 4px padding으로 기존 행 높이를 유지한다. 테이블의 교차 행 배경은 `card.bg` `#1D2025` / `card.stripe` `#2B2E35`이다.
- 무료 아이콘의 디자인 원본은 [Lucide 아이콘 목록](https://lucide.dev/icons)이다. 현재 사용 중인 moon, camera, chevron-down, chevron-right, check, monitor, refresh-cw, user, external-link를 기준으로 구현 자산과 출처를 맞추고, 선 끝과 꺾임은 각지게(`stroke-linecap="square"`, `stroke-linejoin="miter"`) 그린다. 설정(조절 막대), 테마(마름모 해), 대기(각진 모래시계), 접기, 스냅샷은 dfragon-design [아이콘](https://github.com/blahaj94/dfragon-design/blob/main/design/icons.md)의 DFragon 아이콘을 쓴다.
- 캐릭터 이미지: `https://img-api.neople.co.kr/df/servers/<serverId>/characters/<characterId>?zoom=<zoom>`.
- 아이템 이미지: `https://img-api.neople.co.kr/df/items/<itemId>`.
- 서약 대표 이미지는 임시 [발키리 이미지](https://bbscdn.df.nexon.com/data7/showroom/static/icon/oath_09_valkyrie/00001.png)를 사용한 상태다. 이 그림으로 실제 서약 종류를 판정하지 않는다. 종류별 자산 매핑은 후속이다.

장비 슬롯은 반지름 없는 면에 아래 2px 바의 희귀도 색으로 등급을 보인다.

| 장비 희귀도 | 색상        | 장비 희귀도 | 색상        |
| ----------- | ----------- | ----------- | ----------- |
| 커먼        | `#FFFFFF`   | 언커먼      | `#68D5ED`   |
| 레어        | `#B36BFF`   | 유니크      | `#FF00FF`   |
| 에픽        | `#FFB400`   | 레전더리    | `#FF7800`   |
| 크로니클    | `#FF6666`   | 태초        | `#50E3C2`   |

마법부여 표시색은 종결 `#50E3C2`, 준종결 `#FFB400`, 기타 `#FFFFFF`다. 등급 텍스트를 함께 표시하며 색만으로 판정 결과를 전달하지 않는다. **판정 기준이 없는 실제 데이터를 `기타`로 간주하거나 디자인의 예시 등급을 실사용 캐릭터에 복사하지 않는다.**

이미지 로딩은 HTTPS `https://img-api.neople.co.kr`와 `https://bbscdn.df.nexon.com` 두 고정 origin만 허용한다. 실데이터 연결 구현에서 renderer CSP의 `img-src`에 이 origin만 추가하고 기존 `self`, `data:`를 유지한다. `*`, 임의 origin, renderer fetch, Neople API key를 추가하지 않는다. URL은 검증한 식별자와 고정 base로 구성하고 외부 데이터의 임의 URL을 그대로 사용하지 않는다. 네트워크 오류, 누락, 이미지 decode 실패에는 같은 크기의 대체 표시를 둔다. 합성 미리보기는 출처를 기록한 로컬 자산을 사용하며 제품 CSP의 원격 허용을 선행하지 않는다.

## 후속 연결에서 남은 결정

장비, 서약, 강화 표시는 우선 구현할 수 있다. 마법부여 자동 평가와 실제 스킬트리, 서약 종류별 대표 이미지 매핑은 후속 범위다. 아래 결정은 관련 동작을 구현할 때 확인하며 독립적인 화면 작업을 막지 않는다.

- **마법부여 미평가 상태:** 판정 기준을 정하기 전 카드에 안내를 표시할지, 해당 카드를 숨길지 결정이 필요하다. `기타`는 미평가 상태의 대체 값이 아니다.
- **상세 장비 연결:** 기본 정보 상세 창은 캐릭터별로 열고 같은 캐릭터는 재사용한다. 메인 창을 실제로 닫으면 상세 창을 함께 닫으며 장비 확장은 후속 범위다.
- **장비 점수:** 시안에는 값이 있지만 검색 응답에는 없다. 상세 응답의 실제 대응 필드, 누락 표시를 확인하며 계산식을 추정하지 않는다.

## 구현 완료 확인

- 1280 × 800, 최소 1024 × 640, 접은 높이 400과 그 사이 크기, 다크, 라이트에서 카드와 입력, 상세 버튼이 잘리지 않는다. 글꼴과 이미지 실패도 레이아웃을 무너뜨리지 않는다.
- 한 슬롯을 넘겨도 다른 슬롯은 유지된다. 이름, 서버, 상세 버튼 조작은 면 전환을 일으키지 않는다. 키보드 포커스가 보이고 중첩 버튼이 없다.
- 캡처 여부와 무관하게 이름과 서버를 수정할 수 있다. 카드 중앙의 진행 표시, 0건, 최고 명성 대체 표시, 429와 네트워크 실패를 구분한다.
- 이름, 서버 변경 또는 capture 종료 후 늦은 응답이 이전 캐릭터를 복원하지 않는다. 장비와 서약의 부위, 색상, 칭호, 오라, 크리쳐가 각 원본 보드와 일치한다.
- 상세 A안의 카드 선택, 모션 감소, 창 열기, 닫기와 재열기를 실제 Electron에서 확인한다. 실데이터에 예시 마법부여 등급을 표시하지 않는다.

검증 명령은 [scripts 안내](../../scripts/README.md#native-validation)를 따른다. Desktop 변경 시 `pnpm --filter @dfragon/desktop test`, `lint`, `build`를 영향 범위에 맞게 실행한다. `build`는 typecheck를 포함한다. 합성 fixture의 시각 확인과 Windows 제품의 캡처, 검색, 별도 창 성공을 구분해 PR에 기록한다. 이 이관 문서만 변경할 때는 문서 연결, 내용, diff를 확인하고 앱 빌드를 반복하지 않는다.
