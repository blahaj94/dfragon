# OCR 자료실

이번 요청은 별도 Linux 서버의 개인 OCR 자료 관리 API와 SPA, 기존 패스키 연결을 채택한다. 이 PR의 구현·검증에 적용하고 사용자 merge 후 다른 작업에도 적용한다. 후속 요청으로 Desktop의 로그인 중 Print Screen 수집 전송을 채택한다. 아래 Desktop 연결 변경은 이 PR에서 구현·검증하고 사용자 merge 후 활성화한다. 자동 업로드 큐·네트워크 재시도·동기화 충돌·학습·데이터셋 버전 확정·자동 선별은 범위 밖이다. 운영 서버·계정·DNS 변경 성공을 코드 검증으로 대신하지 않는다.

## 원본과 정답

서버가 원천 데이터를 소유한다. 캡처 묶음마다 원본 PNG 한 장과 슬롯별 크롭 좌표·수집 종류·시각·원본 해상도·UI 배율 및 확인 출처를 저장한다. 크롭은 원본에서 요청 시 생성하며 원본·정답을 모델 결과로 덮어쓰지 않는다. UI 배율 미상과 추정·게임 설정 값을 구분하고 초기 선별 조건으로 강제하지 않는다. 선택하지 않은 영역을 detection 정답으로 간주하지 않는다.

공대원창 후속 요청은 수집 종류 `raid`와 화면 위치 1~12의 닉네임 크롭을 기존 저장·정답·조회·평가에 연결하는 범위로 채택하며 사용자 merge 후 적용한다. `hud`·`participants`는 기존 1~4 제한을 유지한다. 공대원 행 번호는 캡처 당시의 화면 위치이며 캐릭터 식별자가 아니다. R/Y/G·싱글과 장비 점수 판독값은 자료실 데이터에 추가하지 않는다.

SQLite 한 transaction으로 원본과 모든 샘플을 저장하며 부분 저장을 성공으로 반환하지 않는다. 같은 캡처 ID·같은 내용 재전송은 중복 저장하지 않고 다른 내용은 충돌로 알린다. 저장 한도를 넘으면 거절하고 기존 데이터를 자동 삭제하지 않는다. PNG bytes 합계 상한과 실제 디스크 사용량은 구분한다.

실제 캡처 정답은 사람이 입력한다. 미작성 null, 제외 boolean과 원본을 보존한다. 빈 새 문자열은 정답으로 받지 않는다. 분할은 NFC 정규화한 정답 닉네임 단위로 관리하며 같은 닉네임의 샘플이 train/val/test에 나뉘지 않게 한다. 정답 수정으로 이미 배정된 분할이 달라지면 명시 확인을 받는다. 미작성은 미배정이다. 후속 사용자 요청으로 아래 최초 자동 분할·추가 배정 계약을 채택한다. 내려받은 자료를 로컬에서 임의로 재분할한 결과까지 보장하지 않는다.

전체 다운로드는 시작 시 함께 읽은 정답·메타데이터·분할 목록과 변경되지 않는 원본·생성 크롭을 포함한다. 제외·미작성도 내려받을 수 있으며 영구 데이터셋 버전은 만들지 않는다.

## 최초 자동 분할과 추가 자료

정답 완료·미제외 실제 자료의 이미지 수·고유 NFC 닉네임 수·문자군 및 개별 문자 빈도를 보여준다. 사용자가 train/val/test 이미지 비율을 직접 입력하며 고정 기본 비율·장기 목표 비율을 두지 않는다. 닉네임 단위로 묶어 이미지 규모와 문자 분포를 근사하고 실제 배정과 목표 차이를 표시한다. 문자군 통계는 정답의 문자 수 기준이며 영문·숫자·기타를 특수문자에 합치지 않는다. 희귀 문자의 모든 분할 출현은 필수 조건이 아니다.

미리보기는 읽기 전용이다. 기본 모드는 기존 배정을 유지하고 아직 배정하지 않은 닉네임만 배정한다. 기존 train/val/test 배정을 바꾸려면 재배정 선택과 변경 닉네임 수를 확인한 명시 적용이 필요하다. 사용자가 수동으로 미배정을 선택한 닉네임은 재배정 옵션과 무관하게 유지하고 그 수를 표시한다. 해당 닉네임의 분할 버튼으로 다시 배정할 수 있다. 미리보기 이후 자료·정답·제외·배정·초기화 상태 또는 비율이 바뀌면 적용을 거절하고 다시 미리보기한다. 배정과 자동 추가 활성화는 한 transaction으로 저장한다. 서버 시작·배포는 기존 데이터 재배정의 승인이 아니다.

최초 적용 후 정답을 저장한 새 미제외 닉네임은 train에 배정한다. 기존 닉네임은 기존 분할을 따르며 val/test 닉네임의 새 크롭도 해당 분할에 추가될 수 있다. 명시적으로 미배정으로 바꾼 기존 닉네임을 자동 이동하지 않는다. 정답 변경으로 다른 분할에 들어가는 경우의 확인 계약은 유지한다. 영구 평가 묶음·서버 데이터셋 버전은 만들지 않으며, Windows 앱이 과거 내려받아 저장한 입력은 변경하지 않는다.

## 패스키와 관리 권한

기존 인증 API의 RP ID·등록 패스키·계정을 유지한다. 선택 설정 `passkey.ocrReturnUrl`이 있을 때만 `clientId: ocr`를 받는다. 복귀는 서버 설정의 정확한 HTTPS `/auth/callback`이며 요청 입력으로 임의 URL을 받지 않는다. 기존 configuration fingerprint에 OCR client와 해당 주소를 추가로 묶어 Desktop/OCR 교환을 구분한다. Desktop fingerprint는 유지하며 같은 DB schema를 사용한다. 기존 challenge·cookie·QR·PKCE·일회용 code 검증은 그대로 적용한다.

OCR 서버가 verifier·기존 API token을 소유하고 HTTPS callback에서 요청별 쿠키와 PKCE로 code를 교환한다. 배포 설정의 계정 UUID와 일치한 계정만 OCR 세션을 발급한다. 첫 로그인 자동 관리자는 없다. 브라우저에는 HttpOnly·Secure·SameSite=Lax cookie만 제공하고 토큰을 localStorage에 저장하지 않는다. 변경 요청은 정확한 OCR Origin을 검사한다. 관리·업로드 권한은 동일하며 별도 역할·임시 업로드 키는 만들지 않는다.

OCR 세션은 메모리에서 최대 8시간 유지하고 process 재시작 시 사라진다. 인증 API에서 기존 세션의 활성 상태를 확인하며 만료된 access token은 단일 refresh로 갱신한다. 로그아웃은 OCR 접근을 먼저 제거한 뒤 기존 세션 종료를 요청한다. 공유 PC 자체의 침해나 강제 종료 때 upstream 세션이 즉시 폐기되는 것까지 보장하지 않는다.

이미지별 `/me` 확인은 인증 서버의 프로세스 전체 60초 창 1,200회·동시 32개 제한을 공유하되 로그인·refresh·logout의 클라이언트별 120회 예산은 소비하지 않는다. 같은 OCR 서버 IP에서 120장을 넘게 조회해도 클라이언트 한도로 거절하지 않으며 매 이미지의 활성 세션 확인을 캐시로 대체하지 않는다. 전체 예산을 넘는 빠른 대규모 조회는 제한될 수 있다.

로그인 시작은 대기 완료·인증 API 호출 중인 요청을 합쳐 전체 100개, 클라이언트별 3개까지 유지한다. 만료·callback 소비·실패는 슬롯을 반환하며 유효한 기존 요청 쿠키를 가진 재시도는 기존 슬롯을 교체할 수 있다. 60초 창에서 시작 횟수는 클라이언트별 10회·전체 60회이며 실패·교체도 횟수를 소비한다. IPv4-mapped IPv6는 IPv4로 정규화하고 IPv6는 동일 /64 대역의 한도를 공유한다. 기본은 직접 peer만 사용하며 `OCR_TRUST_PROXY=single-hop`은 프록시가 전달 주소를 덮어쓰고 서버 직접 접근을 차단하는 배포에서만 허용한다. 재시작·다중 프로세스·분산 공격의 통합 제한은 보장하지 않는다. 이 보안 수정 요청의 구현·검증과 같은 PR에서 채택하고 사용자 merge 후 다른 작업에도 적용한다.

## Desktop 크롭 전송

개발자 화면의 HUD·파티원창·공대원창 수집에서 사용자가 Print Screen을 눌러 로컬 크롭 저장을 마치면, 그 키 입력 시점에 앱 로그인이 완료된 경우 같은 프레임의 원본 PNG와 선택한 슬롯 좌표를 한 묶음으로 즉시 전송한다. 주기적 미리보기·일반 실시간 OCR은 전송하지 않는다. 원본 게임 화면이 전송된다는 안내를 수집 화면에 표시한다. 비로그인 캡처를 나중에 로그인했다고 보내거나 기존 로컬 자료를 일괄 올리지 않는다. 로컬 정답·모델 예측을 서버 정답으로 전송하지 않는다.

Main이 원본 픽셀·좌표와 인증 coordinator의 access token을 소유하고 고정 HTTPS `POST /api/desktop/captures`로 요청한다. Renderer는 업로드 URL·계정·토큰·원본을 제출하는 IPC를 갖지 않는다. 이 경로는 Origin이 없는 Bearer 요청만 받고, 큰 JSON을 읽기 전에 기존 인증 API의 `/me`로 활성 세션과 고정 owner를 확인한다. 쿠키 로그인·정답·분할 변경·export 권한으로 확장하지 않는다. 자료 열람은 아래 별도 읽기 경로에 한정한다. 다른 자료실 API는 기존 owner cookie·Origin 경계를 유지한다.

로그아웃·계정 변경·수집 중단·화면 이탈 때 진행 중 전송을 취소하고 늦은 결과를 새 화면에 적용하지 않는다. 서버가 이미 저장한 요청의 취소는 원격 자료 삭제를 뜻하지 않는다. 한 캡처가 처리되는 동안 다음 단축키는 중복 수집하지 않으며 화면에 전송 중 상태를 표시한다. 전체 전송 예산은 15초다. 401인 경우에만 기존 coordinator의 refresh를 최대 한 번 사용하고 같은 캡처 ID·내용으로 재요청한다. 네트워크 오류·결과 불명은 자동 재전송하지 않고 로컬 저장 유지와 서버 확인 안내를 표시한다.

## Desktop 자료 조회·평가

이번 요청은 개발자 작업 공간에서 서버 정답·크롭을 조회하고 기존 OCR 모델로 평가하는 범위를 채택한다. 이 PR의 구현·검증에 적용하며 사용자 merge 후 다른 작업에도 적용한다. `GET /api/desktop/dataset`과 `GET /api/desktop/samples/:id/image`는 Origin 없는 Bearer 요청에 한해 기존 인증 API의 활성 세션과 고정 owner를 매번 확인한다. 기존 브라우저 경로의 cookie·Origin 경계와 Desktop 업로드 권한을 유지한다. 원본 전체 다운로드·정답 수정·제외 변경·분할 변경 권한은 앱 토큰에 부여하지 않는다.

Main이 고정 HTTPS 주소와 credential을 소유하고 renderer에는 검증한 메타데이터·PNG만 반환한다. 목록의 정답·제외·분할은 함께 읽은 시점의 값이며, 크롭은 변경되지 않는 서버 원본에서 가져온다. 로컬 저장소에 복제하거나 자동 동기화하지 않는다. 로그인 변경·개발자 모드 해제·화면 이탈·다시 불러오기는 기존 조회를 취소하고 늦은 결과를 반영하지 않는다. 조회 요청당 15초 제한과 401에만 최대 한 번 refresh를 적용한다.

정답 입력 탭에서 로컬 자료와 자료실을 구분하고 로컬 미저장 초안을 보존한다. 자료실 정답은 읽기 전용으로 보여주며 사용자가 다시 불러오면 서버 변경을 반영한다. 전체 또는 지정 분할의 정답 완료·미제외 자료를 평가하고 모델 원문 일치율·문자 오류율을 표시한다. 분할을 재배정하거나 모델 결과를 서버에 저장하지 않는다.

## 미니PC 모델 보관과 Windows 학습

후속 사용자 요청으로 실제 모델 파일의 미니PC 보관, REST 조회·다운로드·수동 등록과 별도 Windows 평가 앱의 GPU 학습 연결을 채택했다. 서버 API·보관 화면은 [서버 PR #539](https://github.com/blahaj94/dfragon/pull/539), Windows 로그인·데이터 고정·GPU 학습·평가·수동 등록은 별도 [dfragon-ocr-eval-tool](https://github.com/blahaj94/dfragon-ocr-eval-tool)의 [PR #1](https://github.com/blahaj94/dfragon-ocr-eval-tool/pull/1)에서 구현했다. 앞 절의 학습·로컬 복제 제외는 기존 DFRAGON Desktop 자료 조회 기능에 유지하며, 새 평가 앱은 다운로드 시점의 입력을 로컬 실험으로 고정한다. 서버에 영구 데이터셋 버전을 만들거나 학습을 실행하지 않는다.

자료실의 정답·제외·닉네임 단위 train/val/test 배정이 원천이다. 앱은 정답 완료·미제외·배정된 자료와 선택 모델을 내려받아 해시와 함께 고정하며 서버 배정을 재분할하지 않는다. Windows GPU에서 train으로 학습하고 val로 선택한 모델을 test로 평가한다. 사용자가 등록 버튼을 누르면 새 가중치·사전·평가 요약을 새 모델 ID로 보관한다. 자동 결과 업로드·임의 GitHub 저장소/실행 명령 등록은 제공하지 않는다.

모델의 이름·preset·kind·parentId·등록 시각과 파일 SHA-256을 보관하고 동일 ID 재시도가 기존 bytes를 바꾸지 못하게 한다. 파일과 메타데이터는 원자적으로 저장한다. 일반 파인튜닝은 기존 parent와 같은 preset·사전 bytes를 유지한다. 후속 사용자 승인으로 `expanded` 문자 확장 모델을 추가한다. 부모 preset을 유지하고 부모 사전 전체를 동일 순서의 접두부로 보존하며 새 문자를 뒤에만 추가한다. 기존 ID·사전·가중치는 수정하지 않는다. Windows 앱은 선택한 추가 문자에 필요한 CTC·NRTR 층을 확장하고 기존 문자·공백·특수 토큰의 가중치를 대응시켜 복사한다. 서버는 사전 관계를 검증하되 가중치를 실행하거나 학습 성공을 인증하지 않는다. 원본과 모델 파일에 합산 저장 상한을 적용하며 자동 삭제하지 않는다. 웹 로그인은 기존 owner cookie·Origin 경계를 사용한다. 모델 목록·파일·등록용 Desktop REST는 정확한 허용 경로에서 Origin 없는 활성 owner Bearer만 허용한다.

별도 Windows 평가 앱은 main process가 소유한 웹 로그인 세션으로 `/api/models`, `/api/export/manifest`, `/api/samples/:id/image`를 사용한다. Origin 없는 Bearer를 사용하는 기존 DFRAGON Desktop과 인증 방식·저장소를 구분한다.

첫 지원 모델은 공식 한국어 PP-OCRv5 recognition 학습 가중치이며 웹의 기본 모델 추가로 등록한다. 새로운 패스키·owner·역할을 만들지 않는다. 서버 배포·운영 로그인·프록시 제한 적용과 실제 데이터 학습 성공을 로컬 합성 테스트로 대신하지 않는다.

기본 가중치와 문자 사전은 코드가 소유한 SHA-256에 일치해야 등록한다. 다운로드한 값이나 환경 변수로 기대 digest를 정하지 않는다. 이미 같은 기본 ID로 등록된 파일도 실제 bytes를 다시 검증하며 불일치는 오류로 반환하고 기존 자료를 자동 교체·삭제하지 않는다. Digest와 출처 갱신은 검토 가능한 코드 변경으로 수행한다. 이 보안 수정 요청의 구현·검증과 같은 PR에서 채택하고 사용자 merge 후 다른 작업에도 적용한다.

## Train 합성 보충

Windows 앱이 내려받은 실제 train을 모두 유지하고, 정답 문자 수 기준으로 실제+합성 train의 목표 분포를 설정한다. 한글·특수문자·히라가나·가타카나·한자·영문/라틴·숫자·기타를 구분한다. 사용자가 목표·허용 오차·합성 문자 목록을 직접 정하며, 실제 빈도·필요 보충량·최종 예상과 차이를 본다. 선택한 문자군의 부족분만 새로 계산하고 이전 합성 결과를 자동 누적하지 않는다. 목표 미달·조합 한도는 경고하며 사전·폰트·크롭·학습 입력 오류와 구분한다.

`dnf-ocr-synth`와 Windows 로컬 폰트를 재사용한다. 합성 전 정답 형식(CP949·12바이트·공백 금지), 실제 폰트 렌더링과 유효 사전의 지원 여부를 확인한다. 실제 정답을 수정·삭제하지 않으며 사전 밖 문자가 남으면 구체 문자를 알려 학습 전에 거절한다. 미리보기와 입력 기록을 제공하고 RGBA 글자를 지정한 UI 색상 또는 글자 없는 불투명 배경 조각에 합성해 RGB PNG로 저장한다. 크롭 밖 글자를 자르거나 알파만 버리지 않는다.

닉네임은 사용 중인 실제 val/test의 NFC 정답과 겹치지 않으며 생성 닉네임도 중복하지 않는다. 선택 집합의 문자 사용 빈도를 고려하고 같은 단어의 배경만 바꿔 수량을 채우거나 모든 배경 조합을 복제하지 않는다. 합성은 실행별 train에만 추가하고 실제 val/test 및 과거 실험은 보존한다. 실제 사용 이미지·정답·해시, 목표 설정과 렌더링 정보를 기존 로컬 실험의 실행 폴더에 남기며 기존 test 결과 비교를 사용한다. 새 자료는 다시 가져온 새 실험에서 반영한다. 서버 폰트·학습 환경, 영구 평가 묶음·데이터셋 버전 시스템은 추가하지 않는다.

## 합성 자료 업로드

후속 사용자 요청으로 `dnf-ocr-synth`의 합성 닉네임 PNG·생성 정답·렌더링 정보 등록을 채택한다. 이번 PR의 구현·검증에 적용하며 사용자 merge 후 활성화한다. 기존 Windows 앱의 실행별 로컬 합성 보충은 유지한다. 서버는 합성·폰트 렌더링·학습을 실행하지 않는다.

`POST /api/synthetic-samples`는 기존 owner cookie·정확한 Origin을, `POST /api/desktop/synthetic-samples`는 Origin 없는 활성 owner Bearer를 사용한다. 새 계정·역할·업로드 키는 만들지 않는다. 큰 JSON을 읽기 전에 인증하며 기존 PNG·본문·동시 업로드·합산 저장 한도를 재사용한다.

한 요청은 배경에 합성된 불투명 PNG 한 장과 NFC 정답, 생성 시각, 렌더러 버전·프로필·배율·글자색·배경색을 받는다. 원본 PNG 전체를 한 recognition 샘플로 취급하고 `kind: synthetic`으로 실제 캡처와 구분한다. 이미지·정답·train 배정을 한 transaction으로 저장하며 같은 ID·같은 내용은 중복 저장하지 않는다. 같은 ID의 다른 내용은 충돌이다. 저장 후 정답·원본은 바꾸지 않고 제외·복원만 허용한다. 서버는 입력 정답의 CP949·폰트·실제 글자 일치를 인증하지 않으며 생성자가 렌더러의 검사를 수행한다.

합성은 train 전용이다. 기존 val/test·미배정 닉네임과 충돌하면 업로드 전체를 거절한다. 기존 train 닉네임의 추가 이미지는 허용한다. 합성 닉네임을 수동·자동 재배정으로 train 밖으로 옮기지 않으며 같은 정답의 실제 자료도 train을 따른다. 실제 자료의 자동 분할 통계·목표에는 합성 이미지를 넣지 않는다. 전체 manifest·TAR와 웹 샘플 조회는 합성을 포함하고, 기존 DFRAGON Desktop 자료 조회·평가는 실제 캡처만 유지한다.

## 구현과 검증

독립 Node 24·NestJS process가 API·React SPA를 같은 origin으로 제공하고 SQLite에 원본 BLOB·메타데이터·분할을 저장한다. 기존 API와 HTTP로 통신하며 app source 사이를 직접 import하지 않는다. 배포는 기존 HTTPS reverse proxy와 별도 영속 디렉터리를 사용한다. 명령·입력·한계는 [앱 안내](../../apps/ocr/README.md), 실행은 [인프라 운영 절차](../reference/api-start-development.md#서버-이미지)를 따른다.

인증 client 혼동·비허용 계정·요청 cookie/Origin, 업로드 원자성·재시도·잘못된 PNG·좌표·용량, 정답 수정·분할과 export 내용을 검증한다. UI의 합성 인증 fixture 성공과 실제 패스키/운영 HTTPS 성공은 구분한다. 기존 API의 DB·가상 WebAuthn 검증에는 OCR HTTPS 복귀와 client binding을 포함한다.
